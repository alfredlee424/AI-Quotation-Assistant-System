## 2. 操作與輸入

使用[指定虛擬環境](../venv/)。檔案命令僅支援 POSIX，本批實測 macOS；未驗收 Windows、Linux runtime 或網路檔案系統。

準備以下資料：

1. 原存檔器發布的完整報告，不重新排版、補字或移除尾端換行。
2. 該次存檔器標準輸出的完整回條，另行受控保存。回條不是本核驗器產生，也不能根據報告自行重建後冒充原回條。
3. 由操作者獨立核對的預期操作與第四版 UUID 執行識別。不要只從收到的未知文件自動取值當作外部預期。

兩份檔案均須為工作區外既存的一般檔案、小寫 JSON 副檔名、目前有效使用者擁有，群組及其他人權限全部關閉（一般為 0600）。拒絕同一檔案或同 inode 的硬連結雙輸入、末端符號連結、FIFO、目錄、缺檔、超量、私人環境檔名稱、URI 與工作區路徑。所有參數先驗證，兩份檔案都完成描述符前置檢查才讀取內容。程式不修改權限、不建立目錄、不自動搜尋檔案。

求助：

[`./venv/bin/python development_archive_validation.py --help`](../development_archive_validation.py:22)

以下為操作示例，路徑、操作及識別須改成已受控確認的該次資料，不附帶或建立示例檔案：

[`./venv/bin/python development_archive_validation.py --development-only --operation integrity --run-id 70ea97dd-ef48-4e08-af75-f4074b37fb41 --archive /tmp/quotation-private-reports/integrity-001.json --receipt /tmp/quotation-private-reports/integrity-001-receipt.json`](../development_archive_validation.py:22)

缺聲明、缺參數、重複／縮寫／未知選項均拒絕。沒有自填檢查退出碼、資料庫、修復、覆寫或輸出檔選項。退出碼取自完整核驗的回條，**只是回條記載值，不是本工具觀察到的歷史程序退出碼**。

程式呼叫端可使用 [`validate_development_archive()`](../engine/development_archive_validation.py:85)，明確傳入兩份完整位元組與預期操作／執行識別。只接受位元組，不接受字典、字串、路徑或串流；回傳不可變去識別摘要，不返回原文件、原摘要或執行識別，更不是授權憑證。

## 3. 核驗內容

| 層次 | 核驗規則 |
|---|---|
| 位元組 | 報告最多 128 KiB、回條最多 8 KiB；非空且完整 UTF-8；拒絕 BOM、截斷、多文件、重複鍵、浮點、非有限數與解析失敗 |
| 回條 | 固定版本、完整警語、發布狀態、精確欄位集合、所有能力旗標為真正的關閉布林值 |
| 配對 | SHA-256 與位元組數涵蓋報告原始全部內容（包含空白及尾端換行）；不對重排版內容重新序列化後冒充原檔比對 |
| 執行封套 | 固定版本、完整警語、第四版 UUID、預期操作、狀態、原檢查退出碼及驗證版本一致 |
| 內嵌報告 | 再經既有[嚴格離線驗證](開發檢查報告離線驗證操作說明.md)，涵蓋巢狀欄位、警語、旗標、六表計數與差異一致性；內嵌序列化後仍受 64 KiB 上限 |

未知版本或欄位一律拒絕，不默認前向相容、不自動升版。核驗器固定 v1 wire 契約，不為讀取常數而載入可執行／寫檔的 producer；真實整合測試核對兩方一致性。

## 4. 檔案與失敗語意

- 持有兩份唯讀描述符，單次讀取最多 16 KiB，整份最多各自上限加一位元組；短讀取繼續讀，不把超量截斷成合法輸入。
- 開啟後核對一般檔案、擁有者、權限及容量；讀取前後及兩端全部讀完後再比對 inode、大小、時間、權限與連結數等，常見並行改寫／替換拒絕。
- 這不是跨檔鎖、不可變快照或防惡意管理員機制。祖先路徑、ACL、同 UID 程序、來源信任與保管政策仍由操作者管理；不認證檔案名稱、實際發布位置或保管鏈。外部硬連結或可信程式被替換的風險仍須環境控管。
- 檔案系統 I/O 沒有硬即時期限；程序期限仍由外部可信呼叫端管理。FIFO 以非阻塞開啟後拒絕，不宣稱所有特殊／遠端檔案系統都不會阻塞。
- 失敗不復用舊成功，不輸出部分驗證摘要或敏感錯誤內容；可捕捉失敗關閉描述符。最終輸出仍可能因管線／刷新錯誤留下部分文字，不是新一輪原子存檔。

| 退出碼 | 意義 |
|---|---|
| 0 | 兩份文件核驗有效，記載的原檢查無差異；或單純求助成功 |
| 1 | 兩份文件核驗有效，但記載的原檢查有差異，仍須調查 |
| 2 | 參數／聲明無效，未讀文件內容 |
| 3 | 文件／路徑／權限／平台／核驗／I/O 失敗 |
| 130 | 可捕捉中止，未提供完整結果 |

**沒有回條時，本功能不提供降級通過或重建回條。** 原存檔器發布後發生同步／回條失敗，仍應依原操作說明人工核對，不可因檔案存在就冒充原次成功，也不可自動刪除、覆寫或重試。

## 5. 認證與正式能力界線

收到另一組完整文件時，獨立预期執行識別可阻擋配錯；若兩份文件與預期值都一起被替換，自洽內容仍可通過。舊文件重放、自洽偽造摘要及共同重寫不會因此成為可信來源。

核驗器不證明實際硬連結發布、目錄同步或斷電耐久，不認證回條真實性、不重算資料庫內容，也不證明資料最新、已停寫或同一復原點。原差異與能力旗標語意不變。

仍待可信外部來源關聯／簽章或保管鏈、防重放策略、權威配號歷史／备份最新性、停寫隔離、RPO／RTO、正式遷移回退、DBA／部署／跨平台／跨 DB，以及業務工程身份核准；不能以本功能替代正式監測稽核或解鎖正式報價。
