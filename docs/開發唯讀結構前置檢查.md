# T43 開發唯讀結構前置檢查

> **2026-10-05 對帳續作：** 已新增[開發配號登錄雙庫唯讀對帳](開發配號登錄唯讀對帳.md)，比較明確指定兩份隔離 registry 的完整內容與唯一值歸屬；不修補、不配號。參考端不是經認證的權威來源，兩庫各自讀取快照；內容一致仍不證明最新性、完整快照有效或可恢復配號。本文既有驗收與正式限制保留。

## 1. 交付範圍

2026-10-05 接續[加法式建表與回退開發驗收](開發加法式建表與回退驗收.md)，新增[獨立檢查器](../engine/development_schema_inspection.py)及[隔離測試](../test/test_development_schema_inspection.py)。**只檢查既存隔離 SQLite 檔案的六張開發表結構，不提供正式遷移、修補、還原或恢復配號工具。**

沒有改動應用、配號、原子保存、唯讀查閱或模型入口；沒有新增啟動接線、UI 或客戶輸出。T43／T31／正式 E01–E09 與業務、工程、身份、DBA、部署核准仍未完成。

## 2. 明確操作契約

1. 呼叫端先隔離可信的合成測試庫或開發副本；本工具不認證檔案的真實用途，不能據此連正式 ERP。路徑不是權限憑證。
2. 明確呼叫 [`inspect_development_schema()`](../engine/development_schema_inspection.py:137)，提供既存一般檔案的路徑物件。字串、連線 URL、外部引擎／連線／交易、缺檔、目錄及末端符號連結均拒絕；不從環境設定推測位置，不建立缺少的檔案。父目錄及檔案來源仍須由可信 caller 管理，不宣稱能抵抗惡意管理員或檔案替換競爭。
3. 每次建立自己的檔案唯讀連線，以單一實體讀交易檢查全部六表。檔名特殊字元先編碼，不可注入可寫模式；沒有附加資料庫或外部交易提交。
4. 查看回傳的 [`SchemaInspectionReport`](../engine/development_schema_inspection.py:34)。結構符合只表示當次讀取快照符合目前開發契約，不表示資料完整、服務可寫或正式可用。
5. 有差異則停止並交開發／DBA 審查；不自動產生或執行修復 SQL。資料庫錯誤、鎖等候逾時或中途失敗拋出 [`SchemaInspectionError`](../engine/development_schema_inspection.py:23)，不回傳部分成功、不保存或復用前次結果。
6. 預設期限兩秒，可明確設定大於零且最多三十秒。限制 SQLite busy 等候、掃描階段及虛擬機進度，不是作業系統 I/O 的硬即時中斷保證；連線及讀交易結束即釋放。

完整可執行操作及負例見[測試](../test/test_development_schema_inspection.py)。工具不含自動查找資料庫的命令列入口，避免在未確認來源下誤掃正式庫。

## 3. 比對方式

- 六張表由[開發四表與 registry 契約](../database/development_atomic_schema.py)決定，範圍固定；不要求歷史表存在，也不核准歷史表結構。
- [參考結構](../engine/development_schema_inspection.py:107)每次使用目前套件編譯到私有、無資料的記憶體庫。**只有參考庫建表，受檢檔案永遠不建表。** 不建立磁碟參考檔、不註冊正式模型、不匯入正式連線。
- [現場結構](../engine/development_schema_inspection.py:80)包含宣告型別與容量、欄位順序、可空／預設值、生成欄位、主鍵順序、外鍵順序與動作、唯一／普通／部分／運算式索引、定序與排序，以及完整表定義與額外觸發器。
- 保守比對完整表定義，只忽略引號外空白與大小寫，不改字串常值或引用識別。約束名稱、宣告順序、額外索引／觸發器或語意等價但寫法不同的定義，仍可能報差異，須審查，不能自行忽略。
- 比對的是 SQLite 的**宣告容量**；SQLite 本身不因字串容量宣告就強制限制長度。連線外鍵開關、寫入者設定及跨資料庫容量政策不在本報告的核准範圍。
- 額外歷史／其他表及其觸發器不納入比對、不讀其資料。開發表上的額外索引或觸發器則明確列為差異。

## 4. 輸出與唯讀限制

報告包含固定六表名稱、各表差異類別、預期／實測结构摘要及獨立報告版本；全部正式報價／確認／保存／恢復配號能力保持關閉。差異類別區分缺表、同名非表，以及表定義、欄位、外鍵、索引、額外物件不符。

不輸出現場任意物件名稱、完整建表文字、預設值、路徑、SQL 參數、客戶原文、成本內容或保留號；不寫日誌。摘要只供差異識別，不是簽章、身份憑證、權威 registry 對帳或 migration 版本紀錄。報告不可變只是避免意外修改，不是可交給其他服務的授權 token。

[實際連線允許清單](../engine/development_schema_inspection.py:123)只允許主資料庫結構目錄、必要結構查詢及讀交易控制。除了檔案唯讀模式外，另明確禁止一般資料列讀取、資料增刪改、建表／刪表、設定寫入、附加資料庫及載入擴充套件。測試直接在檢查器使用的連線嘗試這些操作，確認被拒絕。

單一讀交易可在 WAL 並行結構修改時保留當次一致版本；下一次明確檢查才看到新結構。**報告不是持續監控**，不能持有舊通過結果後省略實際查閱／保存驗證。

## 5. 不能替代的驗證

| 情境 | 結構檢查與後續要求 |
|---|---|
| 完整空庫／孤兒保留／已保存庫 | 可以有相同健康結構；不能據此判斷已保存、可開立或可回收號碼 |
| 成本列被刪除 | 結構仍可通過；[完整批次讀取](../engine/development_atomic_snapshot.py:241)拒絕缺列，不補算 |
| 略過約束後寫入未知持久版本 | 結構宣告仍可通過；完整讀取拒絕未知版本，不降版或重寫 |
| 版本約束本身被改動 | 表定義差異明確拒絕；不把未知宣告當現行契約 |
| 舊備份缺少後來使用的號碼 | 健康結構與健康資料都不證明最新性；仍須[權威配號與復原點對帳](開發備份還原驗收.md) |
| 其他資料庫／作業系統 | 本工具只開啟 SQLite；未驗收 MySQL／MSSQL runtime、Windows 或正式部署 |

正式仍待 DBA 核准的現場前置比對、受控遷移版本紀錄、權限／停寫隔離、備份還原與最新性、過往發布版本降版、正式文件映射及業務／工程／身份授權。不能將本工具接成「通過即開放配號／保存」的捷徑。

## 6. 驗收與執行

測試涵蓋 DELETE／WAL、六表逐張缺漏、同名 view、欄位與容量、主鍵／唯一鍵／外鍵／檢查約束、未知宣告版本、生成欄位、運算式及部分索引、觸發器、歷史共存、特殊檔名、唯讀權限、外部交易、逾時與中途錯誤、WAL 結構一致性、資料缺列與未知持久版本反例。

另以全新隔離程序，在匯入前禁止私人環境檔、工作區日誌、網路與正式服務依賴；模組匯入不得建立連線。跨程序參考摘要一致，不依賴父程序的測試替身。
