# 新版工單逐張報價操作說明

## 1. 入口與適用範圍

在專案根目錄執行 [./venv/bin/python four_quote_acceptance.py --local-db](../four_quote_acceptance.py:15)。先停止佔用連接埠的舊服務再重啟，僅重新整理網頁不會更新程式。預設本機 127.0.0.1:8501，不開放外部存取。

- [本機啟動器](../local_quote/bootstrap.py)維持全新程序、清理環境、暫存工作目錄／使用者設定隔離、停用統計及檔案監看。只讀 [`.env`](../.env) 的本機 MySQL 連線與工作組；不載入一般應用的全域 DB／config，不使用模型金鑰。
- 本機模式與隔離目錄模式互斥；禁止初始化、不自動建表，不使用合成資料補真主檔。啟動先檢查既有五張主檔及兩張保存表。
- [新版 UI](../local_quote/dynamic_ui.py)接入本次新增的[純業務核心](../local_quote/dynamic.py)、[逐張工作階段](../local_quote/dynamic_workflow.py)及[逐張保存服務](../local_quote/dynamic_storage.py)，不更改既有資料表結構。
- 本機語意是**規則＋合法候選，不是 LLM**。尺寸精確比對、列明同義詞與部位候選不是通用自然語言理解；沒有自動工程核准、客戶核准或身分驗證。
- [舊四張 UI](../local_quote/ui.py)原樣保留；新版「舊四張歷史（唯讀）」使用 [`BatchStore.list_saved()`](../local_quote/storage.py:446)／[`BatchStore.read()`](../local_quote/storage.py:432)，不修改舊快照格式。舊[四張說明](本機MySQL四張主檔報價操作說明.md)僅作歷史參考。

## 2. 貼工單及確認範圍

1. 先選資料庫提供的產品類別，初始不預選。再貼「品項描述-----正整數」工單；每個品項成一張，成品數不拆成多張。
2. 填操作人與本次人工操作原因。操作人必須為 **1 至 8 字元**，不得前後空白或控制字元；不是數字只能1至8，也不是登入憑證或核准簽章。操作時間由服務端填含時區的 ISO-8601。
3. 按「讀取主檔並分析工單」，此時唯讀取得當次完整主檔。切分與分析結果留在目前工作階段，不配正式號碼、不寫入預覽資料庫。
4. 每張顯示來源原文、原文行號、群組及成品數。展開「完整主檔階層」可見所有主檔路徑、父路徑、必選及未啟用選配；成本明細保留全部啟用階層及缺規格列，不只顯示有價格的葉節點。

工單開頭可包含「環式會議桌(CMT1)」這類產品類別標頭（也接受全形括號）；名稱及代碼必須符合畫面所選主檔，且在品項之前。標頭只用於核對，不會當成規格需求，也不會自動替使用者切換產品類別。

可貼的最小格式示意（仍須當次主檔有對應規格，不是預設答案）：

    工單：示意甲
    平直70X120-----2
    配件：每桌2個銀線盒
    平直70X150-----5
    第2項：線盒共3個
    共用：面無孔

上例若線盒／孔位與無孔條件衝突，仍需人工釐清，系統不自動刪需求。各工單群組內可使用「共用[除1,2]：…」明示例外。新版同部位、同屬性的特定／品項需求優先於共用預設，保留被覆寫來源；同優先級矛盾仍阻擋，不採最後一句勝出。Trello 原始標頭如「(1)20260921-3甲公司/13樓」可直接切分工單群組；8或9位數的日期式前綴僅保留為來源識別，不自動校正或解讀為有效日期。其他標頭可使用明確「來源：…」「工單：…」格式。

### 共用區塊與逐行共用兩種格式

以下兩種寫法可分別輸入，不需要把區塊內每行重複加標頭：

    平直70X120-----2
    平彎70X140-----1
    共用：
    817胡

    噴胡
    腳2片不挖走線孔

等價逐行寫法的尾段為：

    共用：817胡
    共用：噴胡
    共用：腳2片不挖走線孔

- **單獨「共用：」開啟多行區塊，空行不結束**；遇新品項、新工單／來源標頭、另一個明示範圍才結束。只有標頭沒有內容仍阻擋。
- 「共用：條件」只作用於該行，不會自動把下一個無標頭行變成共用。區塊結束後的無範圍文字仍需釐清。
- 共用內容是**同群組所有適用品項**的預設，不是只套用最近一項；區塊的文字邊界不代表只適用標頭之前的品項。不跨新工單群組。
- 六個範例標頭1-1、1-2、2-1、2-2、3-1、3-2也會分開群組；若一次貼入多個範例，各自的共用條件不互相傳遞。它們是替代寫法而非同一工單的追加需求，日常操作應只貼所需的一份。
- 「主席及彎角桌隔板孔位靠單」「列席桌隔板孔位置中」可直接放在品項之間，依同群組產品角色／外型找目標，不須重複「共用：」，也不是只指上一張。「第N項：」的序號是群組內品項序號。

### 語意解析／適用部位表

每張草稿及新版保存歷史均有中文語意表，產品角色與外型另以主席／列席、彎角／平直／平彎等顯示。向右捲動可看全部欄位：

| 顯示內容 | 如何核對 |
|---|---|
| 範圍、群組、群組內適用品項 | 共用／特定／品項；適用品項是序號，不是件數 |
| 部位、需求類型、屬性、需求 | 分開桌面、桌面孔、線盒、桌腳走線孔、隔板及隔板孔；不把孔徑或線盒尺寸當桌面尺寸 |
| 每件量、數量基準、可算本張總量 | 有效且無衝突的可算需求量乘成品數；總量基準不再乘。這是需求數量，不是成本已完整的證明 |
| 來源行、來源原文、解析片語、優先級 | 共用預設優先級10，特定／品項20；原文不改寫 |
| 是否適用、狀態、覆寫需求、衝突需求 | 保留不適用、已被覆寫、重複與衝突；已解析／已匹配不等於可固定 |
| 候選、可掛接部位、已選規格、需求識別及關聯需求 | 對照核心允許的主檔規格、客製掛接及需求關聯，不自行製造路徑 |

「腳2片不挖走線孔」中的2是限制片數，**可算本張總量留空，不能當作2個付費孔**。禁令只作用腳部走線孔，不省略結構必選的其他腳部固定孔。不適用、被覆寫、衝突及待單位也不推算總量。待圖面／訂單的定位要求不產生孔數；既有明確圓孔需求的數量仍可顯示，但外部確認缺口仍擋固定／保存。

另可展開原始欄位，完整查阅 [`normalized_requirements`](../local_quote/dynamic.py:131)：[`kind / part / attribute / targets / value / quantity / basis / origin / priority / effective / override / conflict / status`](../local_quote/semantic_normalization.py:132) 及 [`candidates / custom_paths / selected / requirement_ids`](../local_quote/dynamic.py:137)。中文表採 [`safe_cell()`](../local_quote/dynamic_presentation.py:18) 防公式注入，原始欄位不改寫。語意表是獨立顯示，**不擴充既有13欄報表**。

### 本次六例範圍與不能略過的缺口

僅涵蓋1-1／1-2、2-1／2-2、3-1／3-2六個**各自獨立的四品項來源**，不是把六份接成24張；沒有共用標頭的原始輸入不在本次擴充範圍。

| 同對案例 | 四項成品數 | 核對重點 |
|---|---|---|
| 1-1／1-2 | 2、1、6、2 | 第一項桌面無孔使共用孔靠單不適用，但格靠單仍待核對；其他三项線盒與矩形孔分開 |
| 2-1／2-2 | 2、1、2、2 | 主席及彎角桌的隔板孔適用第1、2項，列席條件適用第3、4項；桌面與腳材分開 |
| 3-1／3-2 | 2、1、4、2 | 每件圓孔1、1、2、2；本張孔總量2、1、8、4。腳片禁挖不混入孔總量 |

同對來源在相同主檔與相同人工輸入下，結構化有效需求、已知成本與缺口應相等，**不表示六例原句全部可報價**。靠單／照圖仍待圖面或訂單核對；台尺、混合或不明的小數尺寸仍待單位確認。實際主檔也可能另缺規格、用量或價格，合成測試不能替現場補足。

### 未知語句不是備註捷徑

- 共用區塊之外未標範圍的獨立原文行阻擋所屬工單，不影響其他已明確分組的工單；尚未出現任何工單／品項前的未知說明仍阻擋全部。可用單獨「共用：」開多行區塊，或逐行共用／「第N項：」「配件：」明示，再分析。這會建立新的來源草稿並撤銷所有未保存固定；不刪除已保存歷史。
- 中文詞之間的斜線可分開核對，例如「817胡/噴胡」保留為兩項需求；分數、規格碼及混合單位不因斜線被拆壞。未理解的每項仍列缺口，不靜默當成備註。
- 非外部確認的來源片段可展開「明確重述與範圍確認」，填**整個片段**的精確重述（包含原有外型、尺寸、孔數等，不只填剩餘未知字）。表單顯示原範圍與本次目標張，必須勾選只作用於本張後提交。
- 共用來源的重述**不自動傳到其他張**；其他張需各自確認。表單透過 [`resolutions`](../local_quote/dynamic.py:17) 合約保存文字、人員、原因、時間，再經同一解析器驗證。
- 台尺／混合單位、定位或加工不猜測；重述不能為空，不能用「忽略」「備註」或刪除必選項取得保存資格。無法表達的結構需求需交受控主檔／工程程序處理。
- **靠單／照圖是「已解析，待圖面／訂單核對」，不是「需要建立客製化新件」。** 目前 UI 只保留待核對提示，不提供無效客製表單，也不提供外部確認重述捷徑。外部確認如何完整重述及解除仍由核心另行審查，**不能為通過而忽略、刪除、改稱備註或只留下其他已知需求**；同片段含外部要求時整段保留待核對。
- 待單位可保持阻擋，或先依真實依據人工核對後，以含明確單位的完整片段重述；不提供自動台尺換算。解析與成本檢查仍需通過，不能只輸入數字來丟失外型／孔數。

## 3. 合法候選與本次臨時件

1. 「合法規格候選」只列當次需求允許的完整路徑、規格碼與說明。不預選多候選第一筆、不採近似尺寸。
2. 唯一且可自動識別的主檔規格會顯示已選值；人工切換合法候選立即重新分析本張。
   同一路徑、同代碼但不同名稱的主檔列會保留為不同候選，不能只靠代碼挑第一筆。新版依主檔完整識別區分，選定名稱及對應價格一起進入快照；同路徑、同代碼、同名稱仍有多筆，或代碼／名稱空白時，仍拒絕載入並顯示相關路徑。
3. 可用客製處理的需求無符合規格時顯示 **「需要建立客製化新件」**；外部確認、待單位與禁止條件不走此表單。選需求允許的既有部位，輸入臨時代碼、說明及採購成本；代碼須以 TMP: 開頭且至多10字元，說明至多40字元。沒有合法掛接部位時須交受控主檔程序，不新增結構。
4. 未知採購成本可留空，真實零成本填0。按「套用本次臨時規格」才提交表單；不會因只打字而自動成立臨時件。
5. 臨時件透過 [`customs`](../local_quote/dynamic.py:12) 合約，只替換本次既有部位的規格，不寫主檔、不新增結構邊。新尺寸可能導致原用量驅動找不到規則；必須補該張正確用量，不沿用近似尺寸的用量。

必選缺項、父子結構不完整、材料方案互斥及否定條件衝突仍阻擋；沒有直接忽略必選或刪缺項的按鈕。

## 4. 補成本、數量與人工稽核

缺價或用量顯示 **「需要建立部件成本」**。未完整時仍顯示草稿與**已知成本小計（非完整合計）**；未知值留空、不是0，不顯示完整報價總額。

每條已選規格列可展開成本輸入，編輯 [`compri / stdqty / stdpar / line_qty`](../local_quote/dynamic.py:14)，不允許直接改總額：

| 畫面欄位 | 意義及限制 |
|---|---|
| 採購單價 | 非負、有限值；未知留空仍阻擋 |
| 用料量 | 非負、有限值 |
| 裁切量 | 正有限值，不能為0 |
| 每件量 | 當核心數量基準為每件時，乘本張成品數 |
| 本張總量 | 當核心數量基準為總量時，不再乘成品數 |

數量基準由來源及核心契約決定，UI 不提供任意切換把量變小的捷徑。「線盒共3個」為該張總量；「每桌2個線盒」為每件量。共用總量未分到各張不得猜平均，須逐張明示／重述。缺成本但已知的數量可以顯示，不代表該列成本已完整。

- 成本欄失焦／Enter 送出即套用；所有欄位皆用最新人員、原因、時間記錄，空白／非法輸入會保留阻擋，不靜默沿用前次有效總額。
- 客製件與重述為表單交易，**按提交才算更動**。保存只處理已提交、已固定的分析內容，不包含尚未提交的表單文字。
- [`overrides`](../local_quote/dynamic.py:14)保存本次列輸入及前後值。操作過程另保留 UI 事件鏈，含每次候選／客製／補價／重述的前後輸入與人員、原因、時間。
- 核心 [`choices`](../local_quote/dynamic.py:10) 在代碼唯一時接受路徑／代碼；同部位同代碼有不同名稱時必須另外帶名稱，不能夾帶單價或用量。UI 事件鏈以 JSON 文字附在固定稽核原因，隨固定文件持久化。歷史 JSON 可查完整事件鏈。此為應用層紀錄，不是不可竄改簽章／登入授權。
- 報價沿用純核心十進位與 HALF_UP 政策：依數量基準 × 用料量 ÷ 裁切量 × 採購單價，乘主檔係數、折扣0%、外加5%稅。符合核心零成本結構規則的空用量不捏造為1。

## 5. 逐張固定、確認及重試

1. 完整一張即可按「固定本張預覽」，其他張未完成不影響。固定重建核驗並檢查欄長／容量，成功才產生該張固定 UUID。
2. 核對固定明細、數量、金額及人工稽核。固定仍無正式號碼。勾選「我已核對本張固定明細、數量與金額，確認保存」後按「確認保存本張」。
3. 保存呼叫 [`DynamicWorkspace.confirm()`](../local_quote/dynamic_workflow.py:181)，使用**同工作階段最新 analysis**及可信主檔摘要；不是把瀏覽器的 ready 旗標當通行證。
4. 每張各自原子保存一份文件及全部明細，確認交易才配置 DQ 開頭的正式單號；沒有四張必須一起保存的限制。完整保存不等於已取得業務／工程核准。
5. 修改本張合法候選或送出成本／表單，若內容版本變更會撤銷本張舊固定與舊勾選資格；其他張繼續。即使改回舊值也不自動復活撤銷的 UUID。
6. 已保存張的所有編輯、固定、確認保存停用。若需修改來源，使用「開始新工單」，不覆寫舊報價；原文／類別在本批已有保存張時鎖定，避免誤把已保存內容當作可修改。
7. 保存失敗／提交回應未知時保留**同一固定 UUID**重試，不重新固定、不另建確認。若工作階段已丟失，先查歷史，再人工查核是否成立；不可猜測失敗並直接重建保存。

## 6. 13 欄報表與歷史

[報表層](../local_quote/dynamic_presentation.py)輸出 UTF-8、Tab 分隔、固定13欄表頭，依 [`logs/ss.txt`](../logs/ss.txt) 的欄位順序；不讀取該檔作測試或報價資料：

| 順序 | 欄位 |
|---|---|
| 1–4 | [`workgroup, ref_no, path, qty`](../local_quote/dynamic_presentation.py:14) |
| 5–9 | [`spc_code, spdsc, stdqty, stdpar, compri`](../local_quote/dynamic_presentation.py:14) |
| 10–13 | [`abndat, abntim, usrno, prgno`](../local_quote/dynamic_presentation.py:15) |

- 每張按鈕、檔名分別標示「草稿未保存」／「正式已保存」；草稿單號及保存日期時間／人員空白，不拿預覽 UUID、張次或虛構號碼充當正式單號。
- 草稿缺成本空白，有真零輸出0；不因缺價而遮掉已知來源／數量。畫面另加階層名稱、父路徑、必選、缺項、數量基準、來源及人工欄，不擴充13欄檔案。
- 日期／時間為實際保存時間的 YYYY.MM.DD／HH:MM:SS，操作人取已保存固定稽核，不取當前輸入框。新版程式碼為 DYNAMIC1；成本及明細取保存文件，不重查現在主檔。
- 新版歷史使用 [`DynamicStore.list_saved()`](../local_quote/dynamic_storage.py:411)／[`DynamicStore.read()`](../local_quote/dynamic_storage.py:399)，同時支援未壓縮 V1 及壓縮 V2；舊四張另以 BatchStore 讀取。查回失敗清除舊畫面，不用前次成功結果冒充。
- 業務文件版本與壓縮封套版本是兩回事：新版業務文件含語意需求，舊業務文件仍由[原引擎](../local_quote/dynamic_v1.py)核驗。舊逐張文件沒有語意欄位時，顯示「舊版歷史未記錄」，成本與13欄下載照常，不以新版解析器补算或補寫歷史。新版保存後語意表一律取持久化文件，不以目前草稿或當前主檔替換。
- 舊版未記錄的異動日／時／人員留空，保存時間另顯示；不把舊保存日期的其他欄位冒充異動欄。舊碼 LOCAL4、實際單號及成本由舊固定資料讀取，提供相同13欄下載及原持久化 JSON。
- 危險公式文字（含前置空白／控制字元及全形公式前綴）在表格投影加單引號；Tab、換行及引號按標準引用規則保護。普通數字、負數、十進位、科學記號、路徑與日期格式不改。防護只作用顯示／TSV，不改主檔或快照；JSON 是原持久化邏輯文件（壓縮時先無損解碼，不輸出儲存封套），不可當成可執行公式或匯入核准。
- 下載不是可匯入草稿，沒有以下載文件繞過當次候選或固定驗證的入口。

## 7. 容量及已知限制（不可省略）

**每張完整保留 catalog（含未選候選、結構、用量規則）、來源、人工稽核與單張明細；需要時才無損壓縮，不截斷、不裁剪、不改表。** 容量為兩道獨立限制：

| 容量 | 上限與行為 |
|---|---|
| 完整邏輯快照 | [8 MiB＝8,388,608 UTF-8 bytes](../local_quote/dynamic_storage.py:45)，包含識別、單號、日期、數值儲存規格及摘要，不只計算主檔或 document |
| 實際儲存文字 | TEXT 65,535 UTF-8 bytes，包含壓縮封套及 Base64 膨脹；超量固定／保存均拒絕 |
| 未壓縮 V1 | 完整邏輯快照在 TEXT 上限內時維持原樣，不為壓縮而改寫小型／舊快照 |
| 壓縮 V2 | 完整邏輯快照超過 TEXT 時，標準庫 zlib 壓縮整份 canonical 邏輯快照，再用 Base64 放入自含封套；不用外部文件或 detached 主檔 |

- [`prepare_document()`](../local_quote/dynamic_storage.py:195) 與 [`DynamicStore.save()`](../local_quote/dynamic_storage.py:352) 共用[容量編碼檢查](../local_quote/dynamic_storage.py:118)。固定時用預留寬度的單號／時間預檢，保存時再檢查實際單號／時間的封套長度；最終壓縮率在邊界可能不同，保存仍以實際長度嚴格拒絕，不能跳過固定預檢繞過上限。超量不補存、不截短，交易失敗完整回滾。
- [V2 封套解碼](../local_quote/dynamic_storage.py:144) 僅接受精確欄位、整數版本2、指定演算法、合法宣告長度及 canonical Base64。先限制儲存文字，後以「宣告解壓長度＋1」有界解壓；拒絕假長度、缺 EOF、尾端垃圾、多個串接流、截斷、損毀、非法 UTF-8、巢狀封套及解壓炸彈，不使用無界解壓／flush。
- 邏輯快照仍是原 V1，摘要比對 canonical 邏輯內容，不比壓縮位元組；封套與內層摘要必須一致，之後仍重建文件核驗及核對全部資料庫明細欄位。保存交易內完整讀回，還要與原待存邏輯快照相同才提交。MySQL FLOAT 的 binary32 投影及 DOUBLE 讀回精確核對政策不變，未新增容忍誤差。
- [`FrozenDynamicQuote`](../local_quote/dynamic_storage.py:65) 三欄、回條、查回 document 與 JSON／13欄下載介面不變；固定請求仍是未壓縮邏輯文件。同一 UUID 的跨程序重試不重建確認，也不需把封套解壓後當作新請求。舊 V1 可直接讀／重試，不需遷移；V2 清單與查回仍完整核驗，不讀外來文件或重新查主檔。

真實大型產品目錄若不可有效壓縮，或完整快照超過 8 MiB，仍可能無法保存；所有人工事件也計入容量。以下合成大主檔的成功不保證現場全部目錄都可存。UI 會顯示上限與容量錯誤；不得以刪除來源／稽核、另建 UUID 重試或修改資料表自行繞過。

沒有符合的規格可以明確建立當次臨時件，但不等於有權新增新的 BOM 部位／結構、定義工程成本或修改主檔。全域範圍不明仍需修原文，片段重述只適用明示單張；不是通用 LLM。服務對資料一致性的核驗不替代來源真實性、使用者權限或業務工程批准。
