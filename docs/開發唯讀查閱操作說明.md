# T30 開發快照唯讀查閱與輸出：部分開發版

## 1. 交付與禁止事項

本功能只查閱 **T29 已保存且完整核驗的開發快照**，不是正式報價、正式授權、客戶輸出或可上線功能。完整身份只是定位資料的欄位，**不是權限 token**；目前沒有登入、角色、工作群組授權或工程核准。只限可信開發人員在本機隔離合成資料環境使用，不應提供給未授權人員或對外部署。

- 不查價格主檔、不重算公式、不保留新號、不保存、不修補、不建表、不 seed。
- 不接原多明細工作區的正式連線，不讀私人環境檔，不新增正式連線設定或模型工具。
- 所有輸出均有不可報價、不可確認、不可保存能力旗標。**「開發保留號，不代表開立」**，沒有假正式報價狀態。
- T28／T29／T30／T31／T47 正式接線、兩次正式確認、產品線／業務／工程／含價／身份權限與 DBA、備份回復、部署及跨 DB 併發核准仍待。階段 5 與 E03／E06／E07 不因此完成。

前置契約與資料建立流程見[整批原子保存開發操作說明](整批原子保存開發操作說明.md)。既有 trial、review 或下載檔均不能換名稱或翻旗標當成已保存快照。

## 2. 入口與安全依賴注入

### 2.1 直接啟動：預設未啟用

獨立入口是 [`development_snapshot_viewer.py`](../development_snapshot_viewer.py)。於專案根目錄執行：

```sh
./venv/bin/python -m streamlit run development_snapshot_viewer.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

畫面會提示「功能未啟用」，沒有查詢或下載；這是刻意的安全預設。入口沒有檔案／URL 輸入器、不探索資料庫、不自動建庫或示範資料，不會偷偷接正式連線。

### 2.2 可信開發 caller 注入已存在的隔離資料來源

[`render(st, reader)`](../utils/development_snapshot_ui.py:28) 與 [`main(reader)`](../development_snapshot_viewer.py:5) 是可操作的注入入口。reader 必須是 [`DevelopmentSnapshotReader`](../engine/development_snapshot_view.py:32)，只公開完整讀取和固定 handle 核驗，不暴露保存／配號。禁止傳入任意字典、回傳字典的自訂假 reader、正式 Session 或正式連線設定。

開發人員應先按 T29 流程在隔離環境完成保存，關閉寫入作業，再以 **SQLite 檔案唯讀模式**開啟同一合成資料檔。以下是放在專案根目錄的開發 Streamlit caller 範例；檔案位置為開發人員在程式中固定審查的路徑，**不得改成 UI／網址參數或環境秘密設定**。示範檔必須已存在，唯讀模式不會建立它。

```python
import streamlit as st
from sqlalchemy import create_engine, event
from sqlalchemy.pool import NullPool
from engine.development_snapshot_view import DevelopmentSnapshotReader
from development_snapshot_viewer import main

# 合成資料、已完成 T29 保存的隔離檔；不是正式 ERP。
# 本段不包含 create_all、seed、reserve 或 save。
if "isolated_t30_reader" not in st.session_state:
    engine = create_engine(
        "sqlite:///file:development-data/t29-synthetic.sqlite?mode=ro&uri=true",
        poolclass=NullPool,
        echo=False,
        hide_parameters=True,
    )

    @event.listens_for(engine, "connect")
    def enable_foreign_keys(dbapi, record):
        dbapi.execute("PRAGMA foreign_keys=ON")

    st.session_state["isolated_t30_reader"] = DevelopmentSnapshotReader(
        engine, source_context="isolated-synthetic-lab-A"
    )

main(st.session_state["isolated_t30_reader"])
```

使用同樣的 Streamlit 啟動方式執行自己的 caller。此範例刻意不隨專案啟動讀庫、不提供資料生成按鈕；可執行的隔離保存與注入驗證見[測試 fixture](../test/development_snapshot_view_fixtures.py)及[真實 Streamlit 測試](../test/test_development_snapshot_ui.py)。

reader 應保留在**目前工作階段**，不要每次重繪重新建立，也不能使用跨使用者全域快取保存 reader、handle、來源或成本。來源環境、引擎或存取上下文更換時必須建立**新的 reader**，不能把舊引擎重新指向另一個資料庫，或原地改寫上下文物件來繞過清除。服務不認證來源是否真的是開發庫，這仍是可信 caller 的責任；不要注入可連正式資料的引擎。

連線池、方言與外鍵沿用 T29：檔案 SQLite、獨立 QueuePool／NullPool、外鍵開啟；不支援記憶體共享連線或自動提交模式。即使引擎只具讀權仍可使用。應停用 SQL debug／payload 日誌與外部追蹤；程式不自行記錄來源或成本。範例只在工作階段保留 reader，沒有秘密全域快取。

## 3. 操作者步驟

1. 從可信開發保存 caller 取得完整 [`DevelopmentSnapshotIdentity`](../engine/development_atomic_contract.py:136)。輸入事業別、批次、請求、預覽、保存識別和開發 schema 版本。
2. 事業別須三位數字；四個識別須分離的 32 位小寫十六進位。schema 須與 T29 版本一致。不自動修剪、猜測、搜尋或列舉身份。
3. 明確按 **「唯讀查閱開發快照」** 才執行 SQL。無操作、填欄位與一般重繪都不讀庫；錯誤格式／schema 在 SQL 前拒絕。
4. 核對整批張數、成品件數、各張開發保留號、獨立精確金額與原批次總額。四品項／11 件仍是四張，不按件拆成 11 張，同路徑不合併。
5. 從**當次完整驗證的批次內**選擇子張，閱讀專屬／共用原文、完整來源、配置、成品數、成本列、每件數、用量／價格證據、精確原值、條件及圖面。各張成本序號仍從五位 00001 開始。
6. 可下載整批 JSON、整批純文字、本張 JSON、本張純文字。沒有保存、配號、正式確認或客戶報價按鈕。

不存在、錯事業別、跨批身份、缺子張／來源／成本、registry 缺漏、被改寫或版本不符時，整批失敗，**不顯示半批**。錯誤訊息不回傳 SQL、連線網址或 payload。失敗會先清除舊數字和下載，修正後必須明確重試。

任一身份欄位更改、reader 實例／來源上下文更換或停用，都會清除舊結果與下載；改回原值不復活。這個清除保護不能撤回已經下載到操作者電腦的檔案，也不能替代瀏覽器及使用者資料保管政策。

## 4. 「當次固定快照」不等於每次重繪即時驗證

[`DevelopmentSnapshotReader.read()`](../engine/development_snapshot_view.py:50) 只委派 T29 的 [`DevelopmentAtomicSnapshotService.read()`](../engine/development_atomic_snapshot.py:241)：同一實體交易核驗 registry header／全部子項，加上開發批次／全部子文件／來源關聯／成本列。沒有以 caller 的子張 row 或保留號另查單張的捷徑，也沒有用摘要替代資料庫核驗。

成功後 reader 簽發 [`VerifiedDevelopmentSnapshot`](../engine/development_snapshot_view.py:25)，封印綁定該實例與完整固定內容。只有此 handle 能進入批次／逐張投影及下載；任意保存結果字典、下載檔、自行改內容重算摘要或另一 reader 的 handle 都不接受。核驗後的展示資料是深層複本，不會改寫保存原值。

**畫面重繪、切換子張和下載，只驗證當次 handle 的程序封印，不會重新查 DB。** 資料庫之後遭修改，既有畫面仍代表上次明確讀取時的固定內容；要看目前資料，必須再次按「唯讀查閱開發快照」重新核驗整批。重新讀取失敗會清除該畫面的舊結果；不宣稱下載當下的 DB 又驗證過一次。下載按鈕不觸發自動重讀。

程序封印不是登入簽章、防管理員簽章或工程核准；能控制 Python 程序或同時改寫資料庫所有副本與摘要的管理員不在此安全界線內。正式不可變保護、唯讀權限、稽核與授權仍需另行核准。

## 5. 完整輸出、安全呈現與精度

- [`batch_view()`](../engine/development_snapshot_view.py:115) 保留整份 T29 保存結果及有序總覽，原建立時間、身份、版本、摘要、來源、保留映射與全部子張均保留。
- [`child_view()`](../engine/development_snapshot_view.py:120) 保留自己完整子文件／成本列、自己的保留映射、完整批次身份／摘要／建立時間、原固定政策及**整份來源工單**。批次總額明確標為「整批原始固定總額，非本張金額」，自己金額在完整子文件內。
- [`export_snapshot()`](../engine/development_snapshot_view.py:173) 只接受已核驗 handle，不能把任意 view 字典直接下載為可信結果。整批與逐張為兩種新開發文件類型，包含文件版本、內容摘要、非正式警語、機密提醒、當次固定快照語意及全部相關原值。
- 金額保持 T29 原十進位字串，不轉浮點或重跑公式／折扣／稅。原未稅、稅、含稅與成本差額不湊數；例如 0.34＋0.02 與 0.35 的 -0.01 差額照原值保留。批次總額直接使用原保存總額，不重新計價。
- 來源原文、內層 JSON 字串的空白及精確小數不截短。「孔靠單」與「無孔有桌下走線」只呈現原文，不選配、不加孔或收費。
- 畫面所有來源／標籤／證據使用安全純文字，不把原文交給 Markdown、HTML、連結或圖片元件；不會自動載入原文裡的外部網址。
- 本批只提供 UTF-8 JSON 與純文字，不提供 CSV／HTML／PDF，因此不執行 CSV 公式或 HTML／Markdown。純文字人類可讀段落後附完整原值；長資料可在畫面展開，**下載不截斷**。
- 檔名僅由驗證過的三位事業別及批次／子張十六進位識別組合，不使用原始單號、標籤或原文路徑。不要把純文字內容再次貼入會執行公式或標記的工具後，誤認為仍受此輸出安全政策保護。
- **含成本及商業機密，不得交付客戶。逐張檔仍包含整份來源工單，不能當成「只揭露該品項」的權限過濾器。**

舊預覽、確認、單品組裝／保存、內部試算、非正式 review、保留與 T29 保存均拒絕新文件。舊正式入口另以文件版本拒絕移除外層類型後的開發輸出，不靠翻轉能力旗標開放。沒有提供任何正式轉型或重匯入 API。
