# 固定版本報價流程

本文件為 2026-09-18 後的實作契約，取代舊文件中「LLM 缺項後才理解需求」、「只算葉節點」、未除裁切量及確認時即時重算的描述。

## 1. 端到端流程

LLM 理解需求並提出變更 → 程式按完整路徑驗證 → 啟用合法選配分支 → 查單價與尺寸用量 → 正確成本試算 → 固定版本預覽 → 人工確認 → 保存同一版本快照。

- [`LLMAgent.run()`](../agent/core.py:308)：每輪提供目前草稿與資料庫選單，只允許一個需求提案工具。缺項不再於 LLM 之前攔截。
- [`apply_proposal()`](../engine/configuration.py:163)：原子驗證產品、完整路徑、代碼、每件配件數量；模型不得傳入單價、成本或材料用量。錯誤提案不留下部分修改。
- [`resolve_configuration()`](../engine/configuration.py:77)：問項、計價與快照共用已啟用樹；保存中間節點及零價選擇。
- [`calculate_configuration()`](../engine/pricing.py:18)：從主檔取得成本與用量，付費父節點也計價。
- [`freeze_preview()`](../engine/preview.py:32)：固定草稿版本、選配、金額、用量來源、公式與捨入版本。
- [`checked_preview()`](../engine/preview.py:60)：確認時驗證版本、草稿指紋、預覽內容摘要；不再查主檔或計算金額。

## 2. 數量與成本

產品總數量與每件產品的項目數量分開保存；實際明細數量為兩者相乘。

**成本＝產品總數量 × 每件項目數量 × 用料量 ÷ 裁切量 × 採購單價。**

- 立水：4.5 ÷ 24 × 700＝131.25。
- 三張桌、每張兩個圓孔：3 × 2 × 1 ÷ 1 × 350＝2,100。
- 用料量零合法；裁切量、產品／項目數量必須為正有限數值。
- 負值、非有限數值、缺少單價或用量規則會阻止預覽。
- 報價係數由產品主檔取得，缺少係數阻止計價；稅率仍由系統設定提供。
- 金額採四捨五入至兩位；總計以未逐列捨入值加總後捨入。展示列的捨入總和可能與總額差 0.01，完整文件保留計算政策。

## 3. 明確的 CMT1 政策

以下是目前實作政策，不是假裝主檔已有額外欄位。生產環境應經業務驗收；若產品允許例外，先調整政策及回歸測試。

1. 每個顏色材質容器的美耐板、美耐皿、貼紙纖維板方案互斥；下板独立。更換方案須明確移除舊子樹，不連帶刪除下板。
2. 必選邊只有在父分支啟用後生效；未選木腳不加入木腳工費，未選配木腳噴漆不自動加入。
3. 必選項目只有一個合法候選時可自動補齊。多候選工費依同部位的材料方案與工序名稱精確對應；無法唯一對應就追問，不能拿工序類別當規格代碼。
4. 已存在用量表時，必須使用其指定的驅動部位和該部位所選代碼；缺少該尺寸規則即阻止計價。
5. 完全沒有用量表時，僅 [`PER_ITEM_OPTIONS`](../engine/pricing.py:12) 明列的外型、噴漆、五金、配件、工費類別允許按件 1／1。材料板件、立水、貼面不允許靜默預設。
6. 現階段一個完整路徑只保存一種規格及每件用量；同路徑多種規格須新增正式明細識別後才能支援。

## 4. 固定版本與確認

- 成功試算才設為預覽。文字回覆、無工具呼叫、API 失敗或待確認問題都不能生成預覽。
- 修改或無法驗證的變更使舊預覽失效；精確的確認指令僅提醒按鈕，不写入資料庫。
- UI 兩次確認綁定同一預覽 ID；版本變更需重新確認。
- 確認時主檔即使已改價，仍保存操作者看到的原版本。需要新價格時，先重新產生預覽。
- 已保存報價不可就地修改。重複確認相同預覽會回傳同一單號，資料庫主鍵防止重複寫入；並行請求若發生唯一鍵競爭，可用相同預覽重試。
- 新單號長度 21：Q＋UTC 日期八碼＋預覽隨機識別前十二碼。不是 ERP 原有流水號；如需 ERP 編號，應另接正式編號服務。

## 5. 資料庫與部署

新增 [`QuoteSnapshotDocument`](../database/models.py:284) 對應的快照文件表，保存完整預覽文件，包括產品數量、每件配件數量、加成／折扣／稅、所有項目、版本及內容摘要。
文件與既有規格快照明細在同一交易寫入；失敗全部回滾。既有明細表欄位未變更，不批次重算或改寫歷史報價。

應用啟動的資料表初始化會建立缺少的表；正式環境需由 DBA 審核並預先建立或提供建表權限。不要為升級刪除既有資料庫。舊工作階段草稿沒有固定預覽，須重新預覽才能確認。

本次不修改連線設定，也不執行正式資料庫建表。外部 ERP／實際 LLM API 尚須部署環境驗收。

## 6. 匯入重報

13 欄順序：事業別、來源單號、完整路徑、明細數量、規格代碼、規格文字、用料量、裁切量、來源採購單價、日期、時間、人員、來源程式。

UI 匯入屬於重新報價，產品總數量由操作者輸入；第 4 欄按每件項目數量帶入重報草稿。操作者須確認來源的數量語意適用。
來源列保留不改寫。規格名稱差異需釐清；不合法路徑或代碼不能靜默丟棄後報價。歷史快照成本重現是獨立驗證用途。

## 7. 驗證

測試入口為 [`test/conftest.py`](../test/conftest.py)，每例使用独立記憶體 SQLite，停用實際 OpenAI／Azure，並封鎖 socket 網路。
使用虛擬環境執行整個測試目錄，命令為：`./venv/bin/python -m pytest test -q -p no:cacheprovider`。

涵蓋 LLM mock 端到端、非法提案原子拒絕、尺寸與數量、材料／工費切換、成本公式、歷史與現行成本區分、快照固定、重試、交易回滾及 UI 兩次確認。
測試原始碼可加入版本控制；原始五份 TXT 因含業務資料仍保留忽略，執行資料案例前需在本機提供這些授權測試資料。

## 8. 候選選擇與草稿即時更新（2026-09-21）

- 目前顯示的候選可用純編號、唯一規格名稱、「編號＋名稱」或複製整段選項回答。舊版含代碼與路徑的選項文字仍相容。
- 明確選擇由程式直接提出變更並通過原有產品／路徑／規格驗證，不再要求 LLM 重判。材料方案使用候選自身的完整路徑，而不是父容器。
- 編號只對目前第一組候選生效；待釐清候選優先於一般缺項。名稱重複、編號越界或編號與名稱不一致時保留選單，不猜選。
- 聊天缺項、候選、草稿明細與預覽摘要以中文部件名稱顯示；ERP 識別仍保留在內部驗證、診斷日誌與報價快照。部件名稱缺失時顯示未命名提示，不以代碼替代。
- 選擇後先顯示「已更新草稿」，已回答的缺項移除，繼續詢問下一項。尚未完成試算時，右側仍顯示已選草稿明細及每件產品用量。
- LLM 上下文包含目前聚焦候選、其他缺項與未釐清問題，不傳候選價格。結構缺項優先以具體選單呈現，避免反覆顯示通用歧義警告。
- 選定規格不等於確認其他配件數量或匯入警告；無關待釐清問題仍會阻止預覽。正式報價仍須規格完整、成功試算及兩次人工確認，不因聊天選項直接寫入。
- 診斷日誌記錄候選命中、提案變更、套用前後增刪差異、剩餘缺項與模型錯誤。請以實際增刪差異判斷是否更新，不能只看請求成功或草稿版本增加。

回歸案例見 [`test/test_llm_quote_flow.py`](../test/test_llm_quote_flow.py) 與 [`test/test_ui_preview_contract.py`](../test/test_ui_preview_contract.py)，涵蓋「817胡桃木 → 平直」連續選擇、兩種 Agent 模式、中文顯示及確認前不寫入資料庫。

### 簡短回覆與舊問題複核

- 聊天每輪只顯示「已選結果＋下一題」，不再重列產品數量、全部缺項或完整中文階層。完整明細仍保留在右側。
- 選項名稱唯一時不附部件；同名候選才加短部件名稱以供區分。舊版完整中文選項及 ERP 選項文字仍可回答。
- 尺寸乘號顯示為「60×180」，避免聊天 Markdown 將乘號當成強調符號；只調整顯示，主檔與快照規格原文不變。
- LLM 模式在最後一個候選選完、結構已完整但仍有舊問題時，進行一次唯讀複核。只能保留或移除原問題，不能改選規格、產品數量、配件用量或價格。
- 用量與匯入疑義保留待使用者回答；其他問題只有判定已由目前選擇解決才移除。仍有問題時直接顯示第一個具體問題，不回覆籠統的歧義警告。模型提供的價格內容不當作報價顯示。
- 複核完成且無問題後才試算，正式報價仍需人工確認。複核失敗時保留全部舊問題及已選明細，不產生預覽。
- 已卡住的舊草稿或複核暫時失敗，可在 LLM 模式輸入「重新檢查」繼續，無需重建。規則模式不呼叫 LLM 複核，保留並顯示待回答問題。
- 診斷日誌包含原問題、複核保留／移除結果與失敗原因，不能僅以必選缺項為零推斷所有需求已完成。

短選單及尺寸相容測試見 [`test/test_option_labels.py`](../test/test_option_labels.py)；舊問題連續選擇、唯讀複核失敗與用量保護測試見 [`test/test_llm_quote_flow.py`](../test/test_llm_quote_flow.py)。
