# T45 開發檢查受控接收與原子接收紀錄

## 1. 交付範圍

2026-10-08 新增[受控接收入口](../development_inspection_receive.py)及[128 項測試](../test/test_development_inspection_receive.py)，接續[證據鏈跨程序驗收](開發檢查證據鏈跨程序驗收.md)發現的「完整回條已刷新，但存檔程序仍可能遭硬中止」界線。

**直接啟動固定存檔程序，取得本次完整回條與實際退出碼，重新讀取並核驗報告後，才原子發布接收紀錄。** 不接外部報告、回條、自填退出碼、任意腳本或解譯器，不重建回條、不自動重試、不復用舊結果。

原存檔、受控檢查、四種檢查服務、離線核驗、配號／保存／查閱與應用均不變。這不是正式稽核、來源認證、備份或恢復配號工具；T45／T43／T31、正式 E01–E09 與業務／工程／身份／DBA 核准均仍待。

## 2. 準備與操作

使用[指定虛擬環境](../venv/)。僅支援 POSIX，本批實測 macOS／SQLite；不宣稱 Windows、Linux runtime、遠端檔案系統或其他資料庫已驗收。

操作者須明確準備：

1. 有權讀取的既存隔離開發副本，不得指向正式 ERP。原[唯讀檢查路徑規則](開發唯讀檢查命令操作說明.md)全部適用。
2. 工作區外既存私有目錄，擁有者為目前有效使用者，群組及其他人權限全部關閉，一般採 0700。不建立目錄、不改權限、不接受末端符號連結或私人環境檔目錄。
3. 同目錄內兩個全新且不同的名稱：報告名稱與接收紀錄名稱。兩者皆須以英數開頭，主名稱最多 80 字元，只用英數、底線或連字號，副檔名為小寫 JSON；大小寫折疊後相同亦拒絕。

求助命令：[顯示操作選項](../development_inspection_receive.py:66)：

[`./venv/bin/python development_inspection_receive.py --help`](../development_inspection_receive.py:66)

下列路徑只是示例，不是專案附帶檔案，須替換成已核對的隔離副本與私有目錄：

- 六表完整性：[`./venv/bin/python development_inspection_receive.py integrity --development-only --database ../isolated/source.sqlite --output-directory ../private-evidence --report-name inspection-001.json --reception-name reception-001.json`](../development_inspection_receive.py:66)
- 六表完整快照對帳：[`./venv/bin/python development_inspection_receive.py snapshots --development-only --reference ../isolated/reference.sqlite --candidate ../isolated/candidate.sqlite --output-directory ../private-evidence --report-name comparison-001.json --reception-name reception-002.json`](../development_inspection_receive.py:66)

另支援結構及配號登錄操作，來源參數與[原存檔入口](開發檢查報告原子存檔操作說明.md)相同。參數必須完整、不得重複或縮寫。相對來源及目的路徑以呼叫端工作目錄解讀，送往子程序前改成絕對路徑；不經 shell，不讀標準輸入。

## 3. 執行與資源契約

| 層級 | 行為與限制 |
|---|---|
| 前置核對 | 保持目的目錄描述符，兩個目的均不存在才啟動。既存一般檔／連結／目錄皆拒絕；發布時再以硬連結保證不覆寫競爭勝者 |
| 固定子程序 | 同一解譯器、隔離模式、空環境、關閉標準輸入、非必要描述符不繼承；啟動獨立程序群組 |
| 存檔 worker | 匯入前阻擋私人檔案、網路、資料庫與正式依賴；只允許一次完整命令相符的既有受控檢查子程序 |
| 管線收集 | 標準輸出最多 8 KiB 原始回條；標準錯誤最多 4 KiB，任何內容均拒絕；有界收集而非收完才查大小 |
| 退出判斷 | 兩條管線 EOF 且真實退出碼為 0 或 1 才繼續。輸出有效後卡住、EOF 後不退出、訊號死亡、異常退出或 stderr 皆拒絕 |
| 外層期限 | 存檔程序收集及退出預設 90 秒，大於零且最多 120 秒，由[外層期限參數](../development_inspection_receive.py:78)設定 |
| 內層期限 | 檢查子程序預設 45 秒、最多 60 秒；原檢查服務結構預設 2 秒、其他 10 秒、最多 30 秒。沿用原入口規則，外層可更短並安全拒絕 |
| 失敗清理 | 終止自有程序群組，包括 leader 已退出但仍持管線的檢查後代；等待直屬子程序最多另加 2 秒，關閉管線。不操作其他程序或掃描檔案 |
| 報告讀取 | 相對釘住的目錄描述符唯讀開啟，不跟隨末端連結；先拒絕 FIFO、非一般檔、非私有／非本人檔案及超過 128 KiB，再有界讀取並核對狀態與具名檔身份 |
| 內容核驗 | 原始回條及報告完整通過既有離線契約，核對操作、執行識別、原始位元組摘要、版本、警語、能力與內嵌報告；記載的原檢查退出碼必須等於本次觀察的存檔退出碼 |
| 接收發布 | 完整接收紀錄最多 64 KiB，同目錄 0600 排他暫存、完整寫入、檔案同步、硬連結無覆寫發布、暫存清理及目錄同步 |

子程序建立、檔案系統 I/O、父程序核驗與最終輸出並無硬即時期限。群組清理只適用可信固定程式、不逃逸群組的後代；不是作業系統沙箱或主機故障復原。

## 4. 接收紀錄與輸出

[固定版本接收紀錄](../development_inspection_receive.py:181)含：

- 本次執行識別、操作、狀態、父程序觀察到的存檔退出碼，以及內嵌原檢查退出碼。
- [原始回條文字](../development_inspection_receive.py:193)、原始位元組數及 SHA-256。UTF-8 重新編碼後可還原全部原始回條位元組，包含空白、跳脫、尾端換行，不重新組裝回條。
- 完整離線核驗摘要、該核驗警語、新接收警語與始終關閉的正式能力旗標。

報告本身維持原存檔格式，不複製或重新排版到接收紀錄。回條內仍含原報告的位元組數與摘要。最終標準輸出只有去識別發布摘要、接收紀錄位元組數及摘要，不回顯目的路徑／名稱、來源、SQL、單號或成本，不輸出完整回條。

本次執行識別取自**本接收程序親自啟動並收集的存檔程序**，不是操作者提供的未知文件；仍依賴可信解譯器、程式碼及環境。接收紀錄與摘要不是簽章；可信程式被替換、自洽偽造或整組舊文件重放仍不具來源認證。

本批沒有新增接收紀錄離線驗證命令。既有[雙文件核驗器](開發存檔與回條離線核驗操作說明.md)仍只接原報告及原回條，不直接接受新接收紀錄；若受控取出原回條另作離線內容核驗，也不能驗證接收紀錄所述的歷史程序退出事實。

## 5. 退出碼與故障處置

| 退出碼 | 意義 |
|---|---|
| 0 | 原檢查無差異、存檔退出 0、文件核驗及接收紀錄發布／摘要輸出完成；或僅求助成功 |
| 1 | 原檢查有差異、存檔退出 1，完整接收紀錄已發布；須調查差異，不能視為通過 |
| 2 | 參數／用途／目的拒絕，未啟動存檔；包含任一目的已存在 |
| 3 | 程序、期限、回條、核驗、讀取、發布、同步或輸出失敗；可能已有完整報告或接收紀錄 |
| 130 | 接收程序收到可捕捉中止；可能已有完整檔案，不自動回滾 |

**報告與接收紀錄是先後發布，不是跨檔原子交易。**

| 失敗時點 | 檔案狀態及處置 |
|---|---|
| 存檔失敗／完整回條後死亡／卡住 | 報告可能已完整存在，但不發布接收紀錄；不自行補回條 |
| 報告或回條無效／退出碼不一致 | 保留報告，不發布接收紀錄，不降級為成功 |
| 接收紀錄發布前失敗 | 完整報告保留；可捕捉失敗清理本次暫存，硬中止仍可能留暫存 |
| 接收紀錄發布後同步／摘要失敗 | 兩個完整檔案可能都存在；回失敗但不刪檔假裝回滾 |
| 兩個接收程序競爭相同紀錄名稱 | 只一個原子發布成功；若報告名稱不同，敗者自己的完整報告仍保留，不覆寫胜者 |

不覆寫、不補回條、不回收舊目的、不掃描或清除前次暫存。另一次明確執行須使用兩個新名稱，形成新的執行識別；不是恢復原次成功。

**原檢查退出、存檔程序退出、離線核驗結果及接收程序自身退出，仍是不同層次。** 本批把存檔程序實際退出納入接收紀錄，但接收紀錄也可能在接收程序成功返回前已發布。外部呼叫端仍須觀察本入口的實際退出及完整輸出；不能無限以新增封套替代最外層監督、可信保管鏈或授權。

## 6. 信任界線與尚待事項

- 目的目錄在子程序前後核對身份／私有權限；讀取報告及發布接收紀錄使用原描述符。目錄被移動或替換時可拒絕，但不提供跨程序目錄鎖、祖先 ACL 稽核、防止改走又改回或抵抗同 UID 惡意程序的保證。
- 來源路徑仍可能在前置核對與真正開啟間被替換；不認證來源身份、權威性或資料最新性。雙庫依序獨立快照，不是停寫或同一復原點證明。
- 接收成功不改變原檢查範圍：健康舊備份、整組共同刪除或合法一致重寫仍可能通過；不可據此恢復配號。
- 檔案及目錄同步不等於主機斷電／控制器耐久認證；只有 macOS／隔離 SQLite 程序行為實測。
- 仍待可信外部來源與保管鏈、權威配號歷史、RPO／RTO、正式遷移／回退、DBA／部署／跨平台／跨 DB，以及業務工程身份核准。所有正式核取狀態不變。

## 7. 驗收結果

2026-10-08，指定虛擬環境 Python 3.14.3：

- 首輪 **105 項通過（19.19 秒）**；補強後新增 **128 項通過（22.63 秒）**。
- 完整隔離回歸 **3095 項通過（355.99 秒）**，原有 2967 項全部保留。
- 四操作 × DELETE／WAL × 空庫／完整保留／已保存：真實存檔及檢查子程序、原資料不變、原始回條可在來源刪除後離線核驗。
- 差異退出 1、共同損壞拒絕、成功後重跑拒絕、非法／重複參數、既存兩種目的、目錄／報告替換、FIFO、容量及權限。
- 真實完整回條後死亡／卡住／關閉管線不退出、截斷、stderr、群組後代持管線、收集錯誤／中止與回收。
- 原子發布短寫入、零寫入、同步／連結失敗、競爭單一勝者、發布後輸出失敗保留完整紀錄。
- 新程序匯入／求助無副作用；存檔 worker 實際阻擋私人檔案、資料庫、網路、正式依賴及額外程序。未讀私人設定／工單日誌、未連正式 ERP／真模型，未執行正式建表。
