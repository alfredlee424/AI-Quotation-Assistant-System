# T43 開發六表完整快照雙庫唯讀對帳

## 1. 交付範圍

2026-10-06 接續[單庫六表完整性檢查](開發六表唯讀完整性檢查.md)，新增[完整快照對帳器](../engine/development_snapshot_comparison.py)與[隔離測試](../test/test_development_snapshot_comparison.py)。

用途是比較兩份明確指定的隔離開發副本：各端先通過六表結構及完整內容核驗，再比較全部持久欄位。補上「配號登錄一致、單庫也各自完整，但已保存四表整組遺失或內容已一致改寫」的差異辨識。

**不是權威來源認證、備份最新性證明、正式復原或恢復配號授權。** 不接應用、UI、模型或正式資料庫；不建受檢表、不修補、不合併、不回收保留，不修改配號／保存／查閱服務。T43／T31／正式 E01–E09 及業務、工程、身份、DBA、部署核准仍待。

## 2. 操作契約

1. 由可信開發／DBA 人員準備兩份隔離合成庫或允許的開發副本，先確認讀取權限、來源與比較方向；最好使用已停寫的不可變副本。路徑本身不是開發用途或權限證明，不可據此連正式 ERP。
2. 明確呼叫 [`compare_development_snapshots()`](../engine/development_snapshot_comparison.py:161)，提供參考端與候選端的既存路徑物件。參考端只定義差異方向，不認證其權威性。拒絕字串、連線 URL、外部引擎／連線／交易、缺檔、目錄、末端符號連結、同檔及硬連結自我比對。
3. 工具依序開啟兩端自己的檔案唯讀連線。每端的結構、六表容量預檢、全部內容核驗與對帳摘要都在同一實體讀交易內；不是先用另一連線的完整性報告放行，再另讀資料。
4. 兩端全部通過才回傳[不可變報告](../engine/development_snapshot_comparison.py:48)。報告包含六表差異、唯一值歸屬衝突，以及兩端各自的已保存／保留未保存計數。顯示時須一併呈現非正式警語。
5. 有差異就停止並交開發／DBA 調查，不自動選較新檔、補存、刪列、回收號碼或合併分岔。任一端結構、內容、容量、期限或讀取失敗，拋出 [`SnapshotComparisonError`](../engine/development_snapshot_comparison.py:24)，沒有部分成功或舊成功快取。

完整合成操作與負例見[測試範例](../test/test_development_snapshot_comparison.py)。沒有自動找庫、預設環境連線、命令列掃描、客戶輸出或正式維運入口。父目錄、檔案替換競爭與來源權限由可信呼叫端管理；不宣稱可防惡意管理員或未知來源的惡意資料庫。

## 3. 比對內容及差異解讀

先重用[完整性契約](開發六表唯讀完整性檢查.md)，核對所有保留及完整固定文件、逐張內容、來源關聯與成本列；保留未保存可以合法存在，孤立列／部分缺漏不行。重建只是驗證固定內容，不讀主檔、不重新計價或核准業務語意。

| 報告項目 | 定義 |
|---|---|
| 參考端／候選端列數 | 六張表逐表的完整列數，不只比較最大前綴、檔案時間或總筆數 |
| 遺失列 | 主鍵只存在參考端；以候選端缺少為方向 |
| 額外列 | 主鍵只存在候選端；反轉比較方向後與遺失互換 |
| 變動列 | 同主鍵但任一原始欄位內容不同；固定內容、時間及摘要欄位都參與 |
| 唯一值歸屬衝突 | 同一資料表的相同唯一值在兩端屬於不同主鍵；依完整單欄及複合唯一約束比較 |
| 全表摘要 | 按穩定主鍵摘要索引形成的全表內容摘要；不受插入順序影響 |
| 兩端完整性摘要 | 分別列六表計數、已保存與保留未保存批次數、結構摘要；只代表各自當次讀交易 |

唯一值衝突包含全域保留前綴、完整號、請求／預覽／子報價識別、保存識別，以及批次內的來源品項、配置、位置等複合鍵。跨事業別相同保留號仍是衝突，不按事業別忽略。

實際對帳索引使用 SHA-256，從**核驗過的原始全部欄位**重新計算，不信任資料庫內已有摘要欄位；原始字串不解析後重排或正規化來隱藏差異。內部文件若不符合既有固定契約，先拒絕而非當作可比較的健康資料。摘要不是簽章，安全性依賴雜湊的抗碰撞性。

一筆成本固定內容變動也會改變整批摘要；因每張子文件都保存整批摘要，可能四張子文件都列為變動。變動列數不是獨立業務修改次數，不可直接推成四筆成本都變了。

## 4. 唯讀、隱私及資源限制

- 每端沿用[六表讀取允許清單](../engine/development_integrity_inspection.py:81)：僅主庫六張開發表及必要結構資訊，拒絕其他表資料、寫入、建表、附加資料庫、提交與任意函式。唯讀交易結束回滾並關閉自有連線，不提交或回滾呼叫端的交易。
- 為核驗及比較會讀取完整內嵌來源與成本；操作人必須有權讀取商業資料。報告只輸出已知表／欄名、計數、摘要與固定警語，不含原始身份、單號、來源、成本、路徑或 SQL，不寫日誌。呼叫端亦不可記錄含敏感區域變數的除錯轉儲。
- 每端先預檢**全部六表**再讀取完整內容：保留表頭及保存批次各最多 10,000 列，其餘四表各最多 100,000 列；單列最多 128 MiB 加 4 KiB，六表原始欄位合計最多 256 MiB。多位元文字以位元組計算，超量整次拒絕、不截斷或抽樣。
- 每端核驗完成只留下雜湊索引與計數，再讀下一端，不同時保留兩庫原始內容。索引與解析／重建仍有額外記憶體開銷；上述不是程序記憶體峰值或作業系統 I/O 硬上限，也不更改保存服務的單批容量。
- 預設整次期限 10 秒，允許大於零且至多 30 秒。兩端、摘要與差異彙總共用同一期限，不在第二端重新計時。限制 SQLite 鎖等候、虛擬機進度及各處理階段，但不能硬中斷單次文件解碼、序列化、雜湊或作業系統 I/O。

## 5. 一致不代表可復原或恢復配號

| 情境 | 本工具的結果／限制 |
|---|---|
| 兩端配號一致，候選端已保存四表整組被刪除 | 兩端可各自完整，但四表遺失差異可見；候選端列保留未保存，不推定從未保存 |
| 兩端計數相同，但其中一端合法重建了不同內容及全部摘要 | 逐欄摘要仍揭露同身份內容變動；不是只比計數 |
| 任一端成本部分缺列或六表同樣篡改 | 完整性失敗，整次拒絕，不將共同損壞報為相等 |
| 同秒分岔兩庫配給不同批次 | 揭露全域前綴及完整號的不同歸屬，不自動解決或重編 |
| 兩端共同過期、整組資料全刪或一致重寫 | 仍可能通過並相等；無外部證據不能證明完整歷史或真實性 |
| 第一端讀完後被改動，第二端仍為舊版本 | 當次仍可能相等；不是跨庫原子快照、持續監控或已完成停寫 |
| 唯讀交易中另一連線提交損壞 | 當次保持同一讀快照；下次明確對帳才看到損壞並拒絕 |

本工具可補足已知健康參考副本的六表差異調查，**不能把參考端自動變成權威**。正式仍須外部配號歷史／權威登錄、可信備份來源、停寫隔離、同一復原點、備份加密權限、正式遷移版本、DBA 審核、RPO／RTO、部署及業務／工程／身份核准。尚未驗收 MySQL／MSSQL runtime、Windows、磁碟故障或正式環境。

## 6. 驗收結果

使用[指定虛擬環境](../venv/) Python 3.14.3，合成資料與既有隔離設定，2026-10-06 最終結果：

- [新增測試](../test/test_development_snapshot_comparison.py)：**141 項通過（10.37 秒）**。
- 完整測試目錄：**2180 項通過（220.82 秒）**，原 2039 項全部保留。
- DELETE／WAL、空庫／單獨保留／已保存、四張／11 件、雙向差集、四表整組遺失、合法同身份改寫、建立時間差異、全域與複合唯一歸屬衝突。
- 六表逐欄共同篡改拒絕、兩端缺列、無效文件／儲存型別、結構及觸發器漂移；共同全刪或合法重寫仍相等的限制反例。
- 路徑與特殊檔名、同檔／硬連結／符號連結、容量精確邊界、候選端超量無部分成功、唯讀連線實際拒絕寫入／其他表／提交。
- 兩端各自在結構、內容或摘要階段發生 WAL 並行變更仍維持同交易；跨庫時間差反例、未提交資料不可見、外部交易不受影響、鎖／共用期限與中途失敗後關閉連線。
- 全新程序於匯入前封鎖私人環境檔、工作區日誌、網路及正式依賴，確認匯入不連線，跨程序完整報告一致。

首輪相關測試發現測試預期漏算各子文件共用整批摘要的差異；確認既有保存契約後修正預期，另補安全邊界，再取得上述完整成功結果。沒有改配號／保存／查閱服務。
