# T45 開發檢查報告離線驗證

> **2026-10-07 接續交付：** 新增[受控執行入口](開發檢查受控執行操作說明.md)，固定啟動原檢查並直接取得本次輸出與真正退出碼，再呼叫本離線驗證器。避免手填退出碼或混用旧報告；本驗證器契約不變。僅 POSIX，實測 macOS；不認證来源或最新性，不提供原子報告保存或正式授權。

## 1. 交付範圍

2026-10-07 新增[離線驗證核心](../engine/development_report_validation.py)及[獨立命令入口](../development_report_validation.py)，接續[開發唯讀檢查命令](開發唯讀檢查命令操作說明.md)。填補「原命令退出碼為 0，仍須確認收到完整有效報告」的接收端檢查缺口。

**只驗證收到的報告格式與可檢查的內部一致性，不重新檢查資料庫，不認證報告真實性。** 原四種服務、原命令、應用、配號／保存／查閱均不變。T45／T43／T31、正式 E01–E09 及業務、工程、身份、DBA 核准仍待。

- 標準函式庫實作，不匯入檢查服務、資料庫／ORM、模型、UI 或私人設定。
- 不讀取來源資料庫，不掃描或開啟報告路徑；命令只接收標準輸入，不提供輸出檔、修復或正式授權功能。
- API 接收完整 UTF-8 位元組及呼叫端獨立指定的預期操作、原檢查程序退出碼。命令缺少明確開發聲明或有效參數時，不讀標準輸入。
- 返回不可變、去識別驗證摘要；不返回原報告、摘要雜湊、身份、號碼、路徑、SQL 或輸入原文。所有報價、確認、保存與恢復配號能力維持關閉。

## 2. 嚴格接收契約

只接收目前四種操作及 v1 版本。版本、警語、已知表名、欄位、唯一鍵與各層能力旗標採固定允許清單；未知欄位／版本一律拒絕，未來服務升版須同步重審，不自動升版或忽略新增內容。

| 層次 | 驗證內容 |
|---|---|
| 原始輸入 | 非空、最多 64 KiB、嚴格 UTF-8、恰一份完整 JSON；拒絕 BOM、截斷、附加文件／文字、重複鍵、非有限數、浮點及超深解析失敗 |
| 輸出封套 | 固定版本、預期操作、原檢查退出碼、完成／差異狀態與完整警語一致，能力旗標必須是真正的關閉布林值 |
| 結構報告 | 六表完整有序、差異類別已知且不重複；缺表／非表不混列欄位差異；摘要格式及是否相等與差異狀態一致 |
| 完整性報告 | 六表計數皆有界整數；已保存／未保存保留與表頭總數一致，子文件／來源列相等，成本及每批子張數量上下界合理 |
| 對帳報告 | 固定二表或六表順序，遺失／額外／變動數不超過對應資料集，兩端共同主鍵數一致，摘要差異與逐表差異一致 |
| 唯一值衝突 | 僅允許目前單欄／複合唯一鍵，固定順序、不重複、正整數且不超過兩端可能變動的歸屬數 |
| 六表完整快照 | 兩端巢狀完整性報告分別驗證，結構摘要相同、各表計數與外層對帳相符 |

**不是驗證完整資料庫語意**：原始資料列未包含在去識別報告中，不能從計數重建並核驗資料。驗證器只檢查字串摘要格式及相等關係，不重算資料庫內容或預期結構摘要，也不驗證簽章。整份合法偽造／一致改寫／舊報告可以通過，甚至來源資料庫已刪除仍可通過。測試特別保留這些反例，避免誤稱安全認證。

## 3. 操作方式

使用[指定虛擬環境](../venv/)，求助不讀輸入或連線：

[`./venv/bin/python development_report_validation.py --help`](../development_report_validation.py:13)

呼叫端必須先**獨立取得原檢查程序真正退出碼**，確認為 0 或 1，再將對應完整標準輸出送入此命令：

[`./venv/bin/python development_report_validation.py --development-only --operation snapshots --inspection-exit-code 0`](../development_report_validation.py:13)

這個範例只在原完整快照檢查確實退出為 0 時適用；由受控呼叫端提供標準輸入並關閉輸入端。原檢查若為差異退出碼 1，必須傳入 1；若為 2、3、130、被終止或根本未取得退出碼，停止處理，不能以之前的報告或自行填 0 代替。

可用操作是結構、完整性、配號登錄、完整快照，名稱與[原命令](開發唯讀檢查命令操作說明.md)相同。參數不接受縮寫、重複旗標或未知選項。離線命令不負責啟動原檢查，也不驗證呼叫端提供的退出碼來源。

**不要只看 shell 管線最後一個程序的退出碼來推定原檢查成功。** 管線最後可能是本驗證器，而非原檢查程序。既存報告沒有來源路徑／執行識別，無法證明它來自這次指定的資料庫；安全工作流程仍須由外部受控機制維持程序、退出碼、輸出與來源的對應。

API 為[離線接收函式](../engine/development_report_validation.py)，必須提供完整位元組、預期操作與原檢查退出碼。不接受字典、文字字串、檔案路徑、連線或部分文件。呼叫成功只返回精簡驗證摘要，不提供正式入口可使用的權限 token。

## 4. 退出碼與 I/O 限制

| 退出碼 | 意義 |
|---|---|
| 0 | 有效且原檢查無差異的報告；或單純求助成功 |
| 1 | 報告有效，但原檢查完整完成後發現差異；仍須停止調查，不能當通過 |
| 2 | 缺聲明、未知／重複／不完整參數；未讀輸入 |
| 3 | 報告無效、與預期不符、解析或輸入／輸出失敗 |
| 130 | 可捕捉的人工中止 |

有效結果輸出獨立驗證版本、操作、原檢查退出碼、狀態、完整警語及關閉的能力旗標。求助也是 0，故接收者仍須確認完整驗證摘要，而非只看退出碼。錯誤使用固定訊息，不輸出輸入值或堆疊；成功後再失敗不復用舊結果。

命令至多讀取 64 KiB 加一位元組以判斷超限，不截斷後接受；**仍需等待 EOF，沒有讀取逾時或作業系統 I/O 硬中斷保證**。可信呼叫端應設定外部程序期限並關閉管線。完整序列化後才輸出，但管線／終端失敗仍可能留下部分摘要，不是原子檔案保存協定。若外部自行保存報告，權限、保留期限、避免覆寫與來源關聯由該機制負責。
