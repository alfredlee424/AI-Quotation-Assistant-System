> **2026-10-05 後續：** 已新增[加法式建表、歷史相容與停用回退開發驗收](開發加法式建表與回退驗收.md)，補測新增開發表、實體建表交易回滾、現行舊讀取入口及保留資料的停用再啟用。以下仍為備份批原始紀錄；正式遷移、實際過往版本降版、權威配號對帳與部署核准仍待。

## 1. 本批界線

2026-10-05 接續 [T31 跨程序故障復原](開發跨程序故障復原驗收.md)，新增[備份還原測試](../test/test_development_backup_restore.py)。**這是隔離 SQLite 的開發演練，不是正式備份工具、正式恢復授權或已完成的 T43。**

不修改配號、保存、查閱或應用服務，不新增操作介面或資料匯入入口；不讀私人環境檔與客戶工單，不連 ERP 或實際模型，不執行正式資料庫遷移。全部資料沿用[合成四品項請求](../test/development_atomic_fixtures.py:19)，不是將非正式試算／核對文件轉成正式報價。

## 2. 演練方式

- 使用[既有測試隔離](../test/conftest.py)及[獨立子程序](../test/development_process_worker.py)，只在每例測試暫存目錄建立開發六表。
- [測試專用備份 fixture](../test/test_development_backup_restore.py:18)使用 SQLite 線上備份機制，來源以唯讀方式開啟，目的檔必須全新；不覆寫原庫、既存備份或目的符號連結。只接受該例暫存範圍，不是任意路徑的維運工具。
- 備份完成後，再將備份還原到另一個新檔。還原不建表、不修改版本、不補資料；備份不直接作為可寫工作庫。
- 以 SQLite 結構與外鍵檢查作第一層檢查，再透過既有服務按完整身份查回整批，核驗配號保留及四張快照表。結構檢查不能替代業務完整性。
- 子程序使用指定虛擬環境並自行封鎖私人檔案、網路及正式服務匯入；唯讀查閱禁止資料寫入。交易同步以明確管線控制，不用任意等待猜測備份時點。
- 備份進度檢查有十秒期限；中斷或來源檔無效時刪除該次新建目的檔，不留下可誤認為成功的還原檔。這不是磁碟故障或作業系統強制終止時的清理保證。

## 3. 驗收矩陣

| 情境 | 驗證內容 |
|---|---|
| 完整已提交批次，DELETE／WAL | 六表逐列一致；原四張配號、建立時間、來源、成品數及整批／逐張 JSON、純文字輸出完全一致 |
| 還原後跨程序重試 | 禁止重新讀時鐘仍回原完整組，不改寫 registry 或快照 |
| 孤兒配號保留，DELETE／WAL | 查閱無快照；保留重試回原組，以原合成請求保存後仍用原保留，不回收、不重新配號 |
| 第二個保留子項／第二張子文件寫入中備份 | DELETE／WAL 各測原寫者後續提交與硬中止；備份只含當時已提交狀態，不含半批 |
| 缺保留子項／子文件／來源關聯／成本列 | SQLite 結構可仍正常，但查閱與保存拒絕，不自動補列或重新計價 |
| 舊而結構完整的備份 | 可以缺少後來已提交的整個 registry；不能僅靠檔案健康或查無資料宣告可恢復配號 |
| WAL 主檔單獨複製反例 | 明確固定舊讀取交易後提交批次；只複製主檔漏掉已提交批次，線上備份則完整保留 |
| 備份逾時／非資料庫來源 | 拋出錯誤並移除新目的檔；來源不變，不發布不完整檔案 |
| 既存目的檔／來源同檔 | 明確拒絕，原始位元組不變 |
| 合成舊版 opaque 資料 | 全庫備份保留二進位內容，不由新服務解碼、補算或遷移；不是舊應用可讀新版本的相容認證 |

四品項／11 件維持四張，各張成本列從五位序號 00001 起；逐張金額、批次總額、原始稅差額、完整共用與專屬原文及非正式警語均沿用既有完整輸出斷言。測試比較固定內容，**不替合成成本或業務規則背書**。

## 4. 正式復原前必須另外核准的事項

1. **停寫與隔離**：由 DBA 及系統負責人制定停寫、權威 registry 隔離及恢復程序。不能讓來源庫與還原庫同時作為可配號主庫。
2. **全庫同一復原點**：配號 registry、全部快照與必要歷史資料必須一致；不可分別挑選不同時間的表備份拼接，也不能以逐張下載檔重建資料庫。
3. **最新性與配號對帳**：本批沒有外部權威高水位、異地日誌或時間點恢復機制。還原檔健康只證明其中資料可讀，無法證明沒有遺失備份之後已保留／已使用的號碼。舊庫查無保留不等於可以重新發號；未完成權威紀錄對帳前禁止恢復配號。
4. **完整性與真實性分開**：SQLite 檢查與文件摘要不是防惡意簽章，不能證明備份來源可信或未被整組重新改寫。來源驗證、加密、簽章／受控清單、存取權限與異地保存仍待設計。
5. **衝突停止**：缺列、摘要不符或內容衝突即停止、保留證據；不得刪除重建、回收孤兒號、改時間、補算金額或使用舊畫面冒充目前有效結果。
6. **版本與回退**：未驗證降版程式可讀新 schema，也未提供遷移回退腳本。正式加法式遷移、資料精度、舊版讀取與回退需另行審查；回退不應刪除新增保留或改寫歷史。
7. **部署驗收**：備份排程、保留週期、復原點／復原時間目標、Windows、主機斷電、磁碟／空間不足、MySQL／MSSQL runtime、故障切換及正式授權都未涵蓋。

因此 **T43、T31 及正式 E01–E09 不因這批測試而勾選完成**；正式 T28／T29／T30／T47 接線、業務／工程／产品線／含價與身份權限仍待。
