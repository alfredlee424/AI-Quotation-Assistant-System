# 對話式報價操作說明（app.py）

適用對象：使用報價助理產出報價單的業務／報價人員。開發與驗證細節見[開發報告](對話式報價開發報告.md)。

## 1. 啟動

在專案根目錄執行：

- macOS／Linux：`./venv/bin/python -m streamlit run app.py`
- Windows PowerShell：`.\venv\Scripts\python.exe -m streamlit run app.py`

瀏覽器開啟 `http://localhost:8501`。

- 主檔取自 [`.env`](../.env) 的 `DB_CONN_STR`、`WORKGROUP`（本機 MySQL／MSSQL），主檔只讀不寫。
- 對話過程只是草稿，不配單號、不寫入資料庫；只有按下「保存到資料庫（ordqdt_ai）」才會寫入（見第 8 節）。
- 舊版單品報價與核對工作區改名為 `legacy_app.py`：`streamlit run legacy_app.py`。

## 2. 畫面

| 區域 | 內容 |
|---|---|
| 左側 | 對話。下方有「復原上一步」「重新開始」。 |
| 右側上方 | 項目名稱、內容（外型尺寸，不重複名稱）、數量、未稅單價與小計、保存後的報價單號；有缺漏的項目以紅字標示「缺 N 項」。 |
| 右側中間 | 「查看項目」切換各項明細。缺規格或缺數量的列為紅字，上方列出缺漏提醒。 |
| 右側下方 | 未稅金額、稅率（稅額）、總額（含稅）。尚有缺漏時紅字註明金額只含已確定的明細。 |
| 最下方 | 下載 13 欄明細（TSV）、操作人與「保存到資料庫（ordqdt_ai，每項一個單號）」按鈕、目前工單文字（可複製，下次一次貼上）。 |

## 3. 第一步：決定產品類別

助理一開始會列出資料庫中的產品類別。回答其中一種即可：

- 編號：`2`
- 代碼：`CMTA`
- 名稱：`侯義興環式會議桌`（句子裡提到也可以，例如「我要訂侯義興環式會議桌」）
- 或直接貼上第一行是 `(CMTA)` 的整份工單

類別決定前，其他內容不會被加入。要換類別請按「重新開始」。

## 4. 方式一：一次貼上整份工單

把整份工單貼到對話框送出，右側立刻產出全部項目的報價。範例（即 [logs/sem.txt](../logs/sem.txt) 的輸入）：

```text
(CMTA)
列席 平直60*150------10
主席 平直60*180------2
轉角 1/4圓60*60------2
共用：每桌1個6cm圓孔、808白橡木、2317胡桃美耐板、3.5夾板
主席及列席 每桌1個：40*15木單掀、單邊置物板、桌面6公分圓孔
列席：黑色漆、下板 4.75MDF、55寬環式腳
列席 隔板40高：932楊胡桃、2317胡桃美耐板、4*8*3.6夾板、4*8*3mm MDF白橡紙
列席 腳：817胡桃木、2317胡桃美耐板、4*8*3mm MDF、4*8*3mm MDF紅木紙、保護膜、美耐皿裁切、色紙貼合
…
```

寫法與 `four_quote_acceptance.py --local-db` 完全相同：

| 寫法 | 意思 |
|---|---|
| `列席 平直60*150------10` | 新增一個項目，名稱「列席」，數量 10。名稱可省略。 |
| `共用：A、B` | 所有項目都套用。 |
| `列席：A、B`、`主席及列席：A` | 只套用到該名稱的項目。 |
| `第2項：A` | 只套用到第 2 項。 |
| `列席 隔板40高：A、B`、`列席 腳：A` | 指定部位（隔板40高／腳／桌面／下板…）。 |
| `隔板40高 隔板靠單：A、B` | 對話中可用：部位後先寫一個規格，冒號後再列同部位的其他規格（等於 `隔板40高 隔板靠單` 加 `隔板40高：A、B`）。 |
| `每桌1個：A、B` | 配件每桌數量。 |

同一規格同時寫在共用與個別項目時，以個別項目為準。同一個項目裡，指明部位的寫法（`下板 4.75MDF`）優先於沒指明部位、會同時套到多個部位的寫法（`3.5夾板` 會套到上板與下板）；所以兩句並寫時，上板是 3.5夾板、下板是 4.75MDF。兩句都指明同一部位但規格不同，才算衝突。

## 5. 方式二：一問一答逐步訂製

1. 輸入品項與數量：`列席 平直60*150 10張`（也可寫 `列席 平直60*150-----10`）。
2. 助理一次問一題必選但還沒決定的規格，並列出主檔候選，例如：

   ```text
   【列席】請選擇 桌面／桌緣噴漆（輸入編號或名稱）：
   1. 櫻桃漆
   2. 白橡漆
   …
   ```

   回答編號（`6`）或名稱（`黑色漆`）。
3. 不想照順序回答時，可以直接說條件，例如 `每桌1個：40*15木單掀、單邊置物板`、`55寬環式腳`、`腳：817胡桃木、保護膜`。沒有寫對象的句子會套用到**助理正在問的那個項目**（剛新增的項目），助理會回覆「已套用到【列席】」。
4. 配件沒寫數量（例如只說 `40*15木單掀`）時，助理會問「每桌幾個？」，回答數字。
5. 全部補齊後助理回覆「✅ 全部 N 項已完整」與未稅、稅額、總額。

### 用一句話修正或補充

回答到一半想改前面的答案、順便補其他規格，可以直接用一句話說，例如上板答錯之後：

```text
上版改 3.5. 下版用 4.75 + 黑色漆
```

助理會回覆「已理解為：上板 3.5夾板」「已理解為：下板 4.75MDF」「已理解為：黑色漆」並套用。規則：

- 用 `+`、`，`、`、`、句點（後面有空白）或「和／還有」分成幾句，每句處理一個規格。
- 每句可以是「部位＋改／換／用＋規格的一部分」。部位用主檔的部位名稱（上板、下板、桌緣噴漆、隔板40高…）或 桌面／隔板／腳；「版」會當成「板」。
- 規格只寫一部分（`3.5`、`4.75`）時，必須在該部位**只對得到一個**主檔規格才會套用。對得到多個時助理會列出來請你指明，不會自己挑；完全對不到的那一句不加入，其他句照常套用。
- 可以加對象：`主席：下板改3.5，桌緣噴漆換白橡漆`。
- 整句只算一步，按一次「復原上一步」就全部退回。

### 再增加項目

訂製完成後隨時可以再輸入新的品項行，例如 `主席 平直60*180 2張`；前面加「加／再加一張／新增」也可以（`加 主席 平直60*180------2`），這些字不會變成項目名稱。之後沒寫對象的句子改套用到這個新項目；要回頭改先前的項目，請寫明對象（`列席：…` 或 `第1項：…`）。

### 項目名稱

- 品項行開頭有名稱（`主席`、`列席`、`轉角`、`主席桌`…，需緊接外型，如 `轉角 1/4圓60*60`）時，報價單用這個名稱。
- 沒有名稱時依序稱為「第1項」「第2項」。
- 兩個項目同名時顯示為「列席（第1項）」「列席（第3項）」，此時 `列席：…` 會同時套用到兩者。

### 修改與復原

| 情況 | 助理的處理 |
|---|---|
| 對同一項目重新說一個規格（先說 `黑色漆`，後說 `胡桃漆`） | 以新的取代，回覆「已取代先前條件」。 |
| 先前用問答選定，之後明講不同規格 | 以明講的為準。 |
| 新的一句與整份貼上的多條件行、或多個項目共用的行衝突 | 不加入，並說明衝突原因。請用「復原上一步」或「重新開始」。 |
| 主檔找不到這個名稱（單行輸入） | 不加入，請確認名稱。 |
| 輸入 `復原`／按「復原上一步」 | 回到上一則訊息之前。 |
| 輸入 `重新開始`／按「重新開始」 | 清空，重新選類別。 |

整份貼上（多行）時，辨識不出的行不會被丟掉，會留在報價單的紅字缺漏中。

## 6. 紅字缺漏怎麼看

| 紅字 | 意思 | 處理 |
|---|---|---|
| 缺規格：桌面／桌緣噴漆 | 必選部位還沒決定規格 | 回答助理的提問，或直接說規格。 |
| 待補數量／成本 | 配件沒有每桌數量，或主檔沒有單價 | 數量：回答「每桌幾個」。單價：需由主檔維護人員補主檔。 |
| 需要建立客製化新件：xxx | 主檔沒有這個規格 | 改用主檔名稱；真的要臨時件請用 `four_quote_acceptance.py --local-db`（見[新版工單逐張報價操作說明](新版工單逐張報價操作說明.md)）。 |
| 已解析，待圖面／訂單核對 | 「靠單／照圖」等需外部確認 | 本頁無法核准，請用 `four_quote_acceptance.py --local-db` 處理。 |
| 同一部位規格或數量衝突 | 兩個條件指定同一部位的不同規格 | 復原後重新輸入。 |

只要有紅字，下方金額就**不是完整報價**，也不能保存。

## 7. 金額怎麼算

- 明細金額 ＝ 數量 × 用料量 ÷ 裁切量 × 單價 × 類別報價係數（`invdoc.quo_rate`）。
- 未稅金額 ＝ 各項目小計加總；稅率 5%；總額 ＝ 未稅金額 × 1.05。金額四捨五入到小數兩位。
- 組裝費、運費等不在產品主檔內的費用不會出現在本頁。
- 與 sem.txt、正式報價單的金額差異見[開發報告第 5 節](對話式報價開發報告.md)。

## 8. 保存到資料庫（ordqdt_ai）

1. 報價單沒有紅字（助理回覆「✅ 全部 N 項已完整」）後，保存區才會開放。
2. 填「操作人」（1 至 8 字元，會寫入明細的異動人員；不是登入帳號）。
3. 核對各項明細與金額後，勾選「我已核對所有項目的明細、數量與金額，確認保存」。對話內容有任何變動，勾選會自動取消，需重新核對再勾。
4. 按「保存到資料庫（ordqdt_ai，每項一個單號）」。成功後右側摘要的「報價單號」欄與對話都會顯示各項目的單號。

保存的內容與規則：

- **每個項目各自一個單號**（同 ERP 一項一單）。例如列席、主席、轉角三個項目會得到三個單號，各自的明細寫入 `ordqdt_ai`，序號都從 00001 開始；同時各寫一筆 `quote_snapshot_document` 作為完整快照。
- 同一次保存的各項目單號**時間相同、流水號依項目順序連續**，例如 `DQ20261117100537_001`、`DQ20261117100537_002`、`DQ20261117100537_003`。中途失敗後補存的項目也接續同一組編號。
- 單號是本系統的 `DQ` 編號，**不是 ERP 的 `QU26A30001-01001` 格式**；本系統不產生 ERP 的 QU 單號，以免與 ERP 自己的配號衝突。
- 這與 `four_quote_acceptance.py --local-db` 是同一個逐張保存服務，可在該畫面的歷史查回每一張。
- **保存後不能修改**：對話、復原都會被拒絕。要建立新報價請按「重新開始」（不會刪除已保存的單）。
- **各項目是分開保存的**：若中途失敗，已保存的項目保留單號，畫面以紅字列出「只保存了部分項目」。此時不要重新輸入，用同一操作人再按一次保存，只會補存剩下的項目，不會重複建單。
- 保存後「下載明細」的 TSV 會帶入各項目的單號、保存日期時間與操作人。
- 不會寫入或修改主檔，也不會自動建表；資料表不符時會拒絕保存。

## 9. 對話紀錄檔

每次對話會在專案的 `logs/` 資料夾寫一個紀錄檔，檔名是對話開始的日期時間，例如 `logs/chat_quote_20261117_105519.log`。

- 第一則訊息送出時才建立檔案；只開啟頁面不會產生空檔。
- 按「重新開始」（或輸入 `重新開始`）之後算新的對話，下一則訊息會寫到新的檔案。重新整理頁面也會開始新的對話。
- 內容是逐則的使用者輸入、助理回覆，以及每則之後的報價狀態（各項目完整與否、小計、未稅／稅額／總額、保存後的單號）；按鈕操作（復原、重新開始、保存與操作人）也會記錄。
- 紀錄檔包含完整的工單原文，請依客戶資料的規定保管；系統不會自動刪除舊檔。`logs/` 已在 `.gitignore`，不會進版本庫。
- 回報問題時附上該場對話的紀錄檔即可重現。寫檔失敗（例如資料夾無權限）不會中斷對話，但該場不會有紀錄。

## 10. 限制

- 助理是**規則＋主檔候選，不是 LLM**：認得主檔規格名稱、既有的工單寫法，以及上面「用一句話修正或補充」的固定句型；其他口語（例如「桌緣要深色一點」）不會被理解。
- 需要臨時件、人工補價、靠單／照圖核對時，請改用 `four_quote_acceptance.py --local-db`；需要整份併成一個單號時用 `--local-db --combined`。
- 未保存的草稿只存在瀏覽器工作階段；重新整理頁面或重啟服務後畫面上的對話與報價會消失（紀錄檔仍在，但不能從紀錄檔自動還原）。需要保留請先保存、複製「目前工單文字」或下載 TSV。問答選定的規格不在工單文字內，重貼時助理會再問一次。
