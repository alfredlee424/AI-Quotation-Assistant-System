## 2. 操作與輸入

使用[指定虛擬環境](../venv/)。檔案入口僅支援 POSIX，本批實測 macOS；未驗收 Windows、Linux runtime 或遠端檔案系統。

必須備妥：

1. 原存檔器發布的完整報告，保持全部原位元組，包含空白、跳脫與尾端換行。
2. 同次受控接收發布的完整接收紀錄，**不是最終標準輸出的發布摘要，也不是原回條**。
3. 由可信外部紀錄獨立核對的預期操作及第四版 UUID 執行識別；不要只從未知輸入自動取值，當成外部预期。

命令求助：

```sh
./venv/bin/python development_reception_validation.py --help
```

以下為範例；先將路徑及執行識別替換成受控保管的實際值，不會自動尋找檔案或資料庫：

```sh
./venv/bin/python development_reception_validation.py \
  --development-only \
  --operation schema \
  --run-id 5a4cd4d2-f1b3-4a96-97d1-b3e9104c616d \
  --archive ../inspection-evidence/report.json \
  --reception ../inspection-evidence/reception.json
```

四種操作仍分別為結構、六表完整性、配號登錄對帳及完整快照對帳；其[命令選項](../development_reception_validation.py:22)與原檢查操作一致。沒有自填退出碼、外部程式、輸出檔、修復、重試或覆寫選項。缺少聲明／參數、未知、縮寫、重複選項或無效預期時，在讀取文件前拒絕。

兩份檔案須為工作區外、目前使用者擁有、群組及其他人無權限的一般 JSON 檔。拒絕末端符號連結、FIFO、相同 inode（包括互為硬連結）、私人環境檔路徑、URI、空檔與超量；不掃描工作區或讀私人設定。

## 3. 核驗契約

[核心核驗函式](../engine/development_reception_validation.py:44)只接完整位元組與明確預期值，不接任意字典、字串、路徑或資料庫連線。僅依賴標準函式庫及既有純離線驗證，不匯入可啟動程序／寫檔的 producer。

- 原報告至多 128 KiB，接收紀錄至多 64 KiB，內嵌原回條至多 8 KiB；原報告內嵌檢查的 64 KiB 契約保持不變。超量拒絕，不截斷後接受。
- 固定接收文件版本、全部欄位及警語，所有正式能力旗標必須關閉。未知或缺少欄位、重複 JSON 鍵、浮點／非有限數、BOM、無效 UTF-8、截斷或附加文件均拒絕。
- 將內嵌原回條文字重新編碼為 UTF-8，核對全部位元組數與 SHA-256，保留原空白及換行；不重新組裝回條冒充原內容。
- 重用[完整報告／回條核驗](../engine/development_archive_validation.py:85)，核對原報告全部位元組、外層版本／操作／識別／狀態／退出碼與完整內嵌檢查契約。
- 不信任接收紀錄保存的離線摘要；重新核驗後逐欄比對版本、警語、操作、狀態、退出碼及關閉旗標。
- 記載的存檔程序退出碼、原檢查退出碼與重驗結果必須一致，且嚴格為整數 0 或 1；布林值不當成整數接受。
- 原報告、原回條、新接收紀錄及發布摘要不互相轉型；既有雙文件核驗命令不改成自動辨識新格式。

檔案入口重用[私有唯讀開啟與有界讀取](../development_archive_validation.py:43)，兩份檔案先開啟核對後才讀內容，保持描述符並在讀取前後、兩端讀完後比對檔案狀態。短讀取可繼續，常見成長／改寫／替換或 I/O 失敗則關閉描述符並拒絕整次。

此機制不是跨檔鎖、祖先目錄／ACL 稽核或抵抗同 UID 惡意程序的保證；保持描述符不等於認證來源路徑與保管鏈。作業系統 I/O 可能阻塞，沒有硬即時期限，外部呼叫端應設定程序期限。

## 4. 結果及退出碼

只返回[不可變去識別摘要](../engine/development_reception_validation.py:30)：核驗版本、操作、原檢查退出碼、**記載的**存檔退出碼、狀態、完整警語與關閉的正式能力旗標。不回傳執行識別、原文、回條、原摘要、路徑、SQL、單號或成本。

| 退出碼 | 意義 |
|---|---|
| 0 | 內容核驗通過且原檢查無差異；或單純求助成功 |
| 1 | 內容核驗通過，但原檢查有差異；仍須調查，不當成通過 |
| 2 | 聲明或參數無效，未讀文件 |
| 3 | 文件／配對／預期無效、平台不支援或 I/O 失敗 |
| 130 | 可捕捉人工中止，未提供完整結果 |

求助也為 0，不能只看退出碼，仍須核對完整新版本摘要。輸出已完整序列化後才寫出，但管線／終端／刷新失敗仍可能留下部分摘要；這不是另一個原子保存協定。成功後再失敗不輸出舊摘要，錯誤訊息不帶輸入原文或堆疊。

## 5. 認證與正式界線

**本工具沒有觀察任何歷史存檔或接收程序。** 記載的退出碼一致，只表示兩份內容符合契約，不能證明程序實際退出、檔案曾完成發布／同步，或接收程序本身成功返回。最外層仍須可信監督及獨立完整退出觀察，不以新增封套無限替代保管鏈。

共同偽造、共同過期、合法重放及合法一致重寫仍可能通過。接收紀錄外層重新排版也可通過；本工具不接其外部發布摘要或簽章，不認證該紀錄本身的發布位元組。內嵌原回條與原報告的位元組關係則必須完全一致。

不證明資料庫目前有效、來源權威／最新性、停寫、同一復原點、備份可用或斷電耐久，不授權正式報價、確認、保存或恢復配號。仍待可信來源與保管链、權威配號歷史、RPO／RTO、正式遷移回退、DBA／部署／跨平台／跨 DB 與業務工程身份核准。
