# T45／T31 開發接收中止與殘留存檔驗收

> **2026-10-08 接續驗收：** [檢查執行中接收中止驗收](開發檢查執行中接收中止驗收.md)補上真正檢查子程序已讀取受檢表、仍持有唯讀交易的中止／繼續／期限／後代清理與重跑競爭，另驗證 DELETE 讀鎖釋放及 WAL 舊快照界線。新增 34 項、完整 3391 項通過。以下四同步點與未驗收敘述保留為原 44 項歷史範圍；新批亦不代表所有 SQL／鎖等待／系統恢復已驗收。

## 1. 本批範圍

2026-10-08 接續[接收紀錄跨程序驗收](開發接收紀錄跨程序驗收.md)，補上**接收程序已遭硬中止、但獨立群組的存檔程序仍執行**時的行為驗證。

只新增或擴充測試及文件，不修改接收、存檔、檢查、核驗、配號、保存、查閱或應用服務。不新增封套、正式監督服務、自動取消、回條補建、掃描清理或自動重試工具。T45／T43／T31、正式 E01–E09 與業務／工程／身份／DBA 核准狀態不變。

**接收者死亡不等於存檔已取消；接收目的不存在也不等於沒有存檔程序仍會發布。**

## 2. 程序、隔離與證據界線

- [隔離 worker](../test/development_reception_worker.py)呼叫原受控接收入口；由原收集器建立獨立存檔群組，仍使用真正的受控檢查子程序、原始輸出及唯讀檢查服務。
- [測試專用同步點](../test/development_active_reception_hooks.py)只注入存檔測試程序；保留原匯入前防護及固定檢查命令，不注入假報告、回條或檢查退出碼，也不修改磁碟上的應用程式。
- 僅測試控制管線傳入存檔程序，不再傳給其檢查子程序。使用管線屏障確認阶段，不用任意延遲猜測時機。
- 父測試先確認存檔程序屬於不同的獨立群組，硬中止並等待接收者，實際觀察其訊號退出及空白輸出；存檔仍停在已知屏障。
- 接著由父測試明確終止存檔群組，或允許它繼續執行原存檔邏輯。測試結束有界清理本次已知群組，並等控制管線 EOF；不操作其他程序。
- 存檔函式返回值透過測試管線回報，**不是父測試對孤兒存檔程序取得的作業系統退出狀態**。控制 EOF 只證明本次控制寫端已關閉，不是正式恢復或斷電耐久證明。
- 使用工作區外合成 SQLite、四品項／11 件開發契約與私有目的目錄。未讀私人環境檔或工單日誌、未連 ERP／真模型、不執行正式建表。

八項正常放行對照亦確認：即使已收到存檔函式返回標記，只要存檔程序尚未真正返回，接收者不發布接收紀錄；放行真正退出後，原接收與全新離線核驗成功。

## 4. 四個同步點與殘留結果

所有案例先硬中止接收者；下表分別描述外部再終止存檔群組，以及放行存檔繼續的結果。

| 存檔同步點 | 外部終止群組後 | 放行殘留存檔後 |
|---|---|---|
| 即將執行檢查、尚未啟動檢查子程序 | 無報告、無暫存、無接收紀錄 | 仍可執行真正檢查並發布報告；回條管線失敗，原函式返回失敗 |
| 完整報告暫存同步後、硬連結發布前 | 無報告、一份完整暫存、無接收紀錄 | 可完成發布並清理自己的暫存；回條管線失敗，原函式返回失敗 |
| 硬連結發布後、清理與目錄同步前 | 完整報告與同內容暫存、無接收紀錄 | 保留報告並完成暫存清理；回條管線失敗，原函式返回失敗 |
| 完整回條刷新後、存檔函式返回前 | 完整報告、無暫存、無接收紀錄 | 原函式可返回原檢查結果 0／1，但死亡的接收者仍不會建立紀錄 |

全部缺接收紀錄情況，原離線核驗命令均拒絕；不能用暫存、原報告或已送達但未持久接收的回條替代。已發布報告仍維持完整內容與私有權限，不因回條失敗刪除報告假裝回滾。

外部終止後的暫存不掃描、不自動改名、不當作已發布。另用新名稱執行會取得新識別、產生新接收紀錄並通過核驗；原報告及暫存位元組保留，新紀錄不能配回舊報告。

## 5. 重跑不是取消或補回條

- **報告已存在：** 相同目的重跑在前置核對拒絕，原檔案不變。
- **只有暫存、報告尚不存在：** 前置核對不把暫存當成目的保留鎖。新接收程序可能先完成真正檢查、發布及接收；它是新身份，不是原執行的冪等重試。
- 舊存檔繼續發布時，硬連結的無覆寫規則拒絕，原函式返回失敗；新報告與新接收紀錄完全不變。仍活著的舊存檔器只清理自己的暫存，這不等於有自動掃描清理服務。

因此，不應以「接收者已退出」或「目前目的尚不存在」推定可安全自動重跑。實際部署仍需最外層可信監督、操作紀錄及殘留工作處置政策，不能靠再包一層封套取得這些保證。
