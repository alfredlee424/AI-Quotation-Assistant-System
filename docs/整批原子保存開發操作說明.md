## 1. 交付界線

2026-10-02 交付真正可呼叫、可測試、可跨程序查回的獨立開發保存服務。**保存的是開發快照，不是正式報價。** 不認證身份、不核准工程、不開立客戶文件、不接 UI／模型／正式單品保存，也沒有部署或執行正式建表。

本服務接受新的嚴格開發型別，而不是將既有非正式文件換名字或翻旗標：

- [開發固定契約](../engine/development_atomic_contract.py)保存完整來源、逐張配置／成本證據／精確金額與版本。
- [原子保存與完整讀取](../engine/development_atomic_snapshot.py)只使用明確注入的隔離引擎。
- [獨立四表定義](../database/development_atomic_schema.py)不加入正式模型集合，不引用舊非正式描述表當作正式文件。
- [T28 兩次非正式核對](整批固定內容與兩次非正式核對操作說明.md)仍不可保存；第零／第一次／第二次核對文件均不能送進本服務。

正式 T29 仍待受控正式預覽、身份授權、工程／業務／含價政策、T47 同版銜接、正式表及 DBA 核准。**T29 僅部分基礎；T28、T31、E03、E06、E07 不因此勾選完成。**

## 2. 開發操作順序

僅在合成資料與隔離暫存 SQLite 檔案操作，勿使用應用正式連線或私人環境檔。完整可執行例子見[合成四品項建構器](../test/development_atomic_fixtures.py:19)及[服務測試](../test/test_development_atomic_snapshot.py)。

1. 呼叫端建立檔案型 SQLite 引擎，使用獨立 checkout 的 QueuePool 或 NullPool，於每條連線啟用外鍵。另設有限連線池等候及作業系統 I/O 政策；不能共用呼叫端實體連線。
2. 只在隔離測試庫明確建立 T47 registry 與四張開發表。[`development_atomic_schema()`](../database/development_atomic_schema.py:11)回傳獨立 metadata、批次、子文件、來源關聯、成本列；metadata 中包含 registry 定義供外鍵解析。已有 registry 時只明確建立四張開發表。**服務不自動建表；這不是正式 migration。**
3. 程式直接建立 [`DevelopmentAtomicRequest`](../engine/development_atomic_contract.py:119)與全部巢狀開發型別；完整來源和固定數字必須已經存在。這不是 UI 輸入器、計價引擎或既有 trial/review 的轉換器。
4. 呼叫 [`build_development_reservation_request()`](../engine/development_atomic_contract.py:390)，取得**同一完整固定內容**的 T47 typed request。以同一隔離資料庫的 [`QuoteNumberReservationService.reserve()`](../engine/quote_number_reservation.py:212)明確保留整組並提交。開發 caller 的這次保留不是正式核准。
5. 將原 typed request 傳給 [`DevelopmentAtomicSnapshotService.save()`](../engine/development_atomic_snapshot.py:200)。不傳 caller 的保留結果字典，不另傳新金額，不自行重新配號。批次、所有子文件、來源關聯、成本列於單一 owned 交易寫入。
6. 用 [`identity_of()`](../engine/development_atomic_contract.py:216)取得完整身份，再呼叫 [`DevelopmentAtomicSnapshotService.read()`](../engine/development_atomic_snapshot.py:241)。讀取要求事業別、批次／請求／預覽／保存識別和 schema 版本，驗證整組而非只讀一列。
7. 網路回應遺失、程序重啟或暫時 busy 後，重送原 typed request。已提交者回傳原完整文件及原建立時間；未提交者原子重試。讀取不存在時回傳無結果，不配號、不補寫。

本批**沒有新增兩次確認 API 或假造確認記錄**。來源歷史與條件／圖面等證據只代表開發固定資料，不解釋為已驗證簽章。未來正式兩次確認須另外綁定同一含號正式預覽、全部子張與有權身份，不能沿用本批保存結果或 T28 非正式 token。

## 3. 全部內容在保留前固定

[`validate_request()`](../engine/development_atomic_contract.py:232)要求：

- 四個分離的批次／請求／預覽／保存識別、事業別、修訂版、來源程式與獨立文件版本。
- 完整來源工單原文、原始單號、來源批次／工單識別、解析版、來源歷史、逐行文字／行號／分類與作用範圍。逐行重建須與完整原文逐字一致；來源品項與子張有序雙向覆蓋。
- 各張穩定子報價／來源品項／配置識別、來源行、位置、成品數、配置修訂、產品類別、標籤、專屬原文、所有適用共用描述，以及完整尺寸、需求、條件、圖面證據。
- 每張有序固定選配與全部成本列雙向覆蓋。同張一個完整路徑只能一列，不同張相同路徑不合併；結構、零價、付費父節點與付費子節點均保存。缺列、未知列、重複列與錯序拒絕，不補零。
- 每列固定配置、規格／部位／選項代碼與描述、單位、原數量、成品数、每件數、實際數、用料量、裁切量、採購成本、成本／單價／金額，以及用量來源、用量證據與價格證據。
- 六項逐張固定金額、未捨入原值、各張係數、共用折扣／稅率、成本展示差額、稅捨入差額；批次六項總額只能是逐張固定金額的精確加總。公式、捨入、價格版本與幣別全數固定。

完整未配號請求寫入 T47 的固定上下文，每張完整內容另寫入保留子項固定內容；保存身份也已在裡面。**任意非空上下文、只保留來源摘要、保留後另附金額，均無法通過本服務。** 內層 JSON 原字串一併固定，空白或鍵序改變也不能冒充原請求。

保存服務在自己的資料庫連線讀取 T47 header／全部有序子項，比對完整請求、摘要、身份、來源、數量、順序、號碼及版本。寫交易取得鎖後再核驗一次，避免讀取與寫入間的內容替換。最終指紋包含完整固定內容、持久保留整組、所有對應及建立時間；它是完整性摘要，**不是授權簽章**。

## 4. 精度、容量及拒絕政策

| 類別 | 本批開發限制 |
|---|---|
| 子報價 | 1–999 張；1000 張整批拒絕，不暗中拆批 |
| 各張成本序號 | 自己的 00001–99999；三位報價尾碼不取代五位成本序號 |
| 整批成本資源 | 最多 100000 列，且同時受固定文件大小限制 |
| 未配號固定請求 | UTF-8 最多 16 MiB；最終含號文件最多 128 MiB |
| 來源 | 最多 10000 行、原文 1048576 字元、單行 65535 字元；原文不截斷 |
| 成品數 | 正整數，最多九位；布林、零、負值拒絕 |
| 精確數字 | 固定十進位字串，最多 18 位整數＋18 位小數；不接受 float、科學記號、非有限值或負零 |
| 逐張／批次金額 | 固定兩位小數；原未捨入字串另存，不重新執行公式或捨入 |
| 正有限數 | 每件／實際／原數量、裁切量、報價係數必須大於零；用料量與價額允許零、不允許負值 |
| 路徑／代碼／列說明 | 路徑 256 字元、代碼及單位 32 字元、列說明 1024 字元 |
| 產品及來源說明 | 產品類別 16、標籤 256、來源原單號／來源說明／解析版 256、呼叫來源程式 80 字元 |

空物件、重複 JSON 鍵、非有限數字、非固定型別、未知／缺少持久文件欄位、超長內容均拒絕。尺寸／條件等證據 JSON 要求完整非空物件與固定序列化；**本層不認證內部證據的業務／工程語意**，不能用隨意寫一個通過欄位取得正式能力。

精確算術僅驗證數量關係、逐張加總與差額，不查價、不執行已固定的成本／折扣／稅公式。兩张未稅各 0.34 必須合計 0.68，不能改成舊整單 0.67；每張含稅額與未稅＋稅額有 -0.01 捨入差額時原樣保留，不調整列價湊平。

容量測試實際保存 999 張；99999／100000 成本序號以邊界函式及重用不可變列的超量拒絕測試驗證，不建立巨型成本 fixture。**不宣稱 99999 個完整成本列已做吞吐／記憶體壓力驗收**；16 MiB 內容上限可能先阻擋。原非正式試算 200 張上限不變。

## 5. 四表與不可變保存

| 新表 | 保存／索引 |
|---|---|
| [`development_atomic_batch`](../database/development_atomic_schema.py:14) | 完整含號文件、固定及最終摘要、建立時間、開發狀態；批次／請求／預覽／保存識別各自唯一；同事業別批次前綴外鍵到 registry |
| [`development_atomic_child`](../database/development_atomic_schema.py:36) | 每張完整文件、保留號、位置、列數；同批子身份及號碼引用持久保留，完整號唯一 |
| [`development_atomic_source_link`](../database/development_atomic_schema.py:55) | 同批来源品項／配置／位置唯一；完整来源工單識別、行號、成品數與該張來源文字投影 |
| [`development_atomic_cost`](../database/development_atomic_schema.py:74) | 批次＋子張＋五位序號主鍵；同張完整路徑／位置唯一；完整精確成本列、配置與證據 payload |

這不是任意內容的簡化 CRUD：批次完整文件和所有子張／關聯／列的欄位逐一重建核驗。讀取與重試也核對所有列的數量及內容；缺張、缺關聯、缺成本、多列、改摘要或改 payload 都拒絕，不修補半批。寫入後提交前再讀回核驗，可拒絕觸發器靜默改寫。

服务只有追加保存與完整讀取，沒有更新／刪除／修補 API。T47 registry 只讀，不更新狀態為已開立、不刪除、不回收。新寫入中途任何錯誤讓四表全部回滾；先前已提交保留永久留下，允許孤兒保留。

**管理員 SQL 權限仍可破壞或協同偽造所有副本與摘要。** 完整性校驗不是防管理員的數位簽章；正式部署仍需唯讀／追加權限、不可變保護、稽核、備份及可信身份。測試以 SQLite authorizer 證明保存／重試／讀取不需要 registry 寫權限，沒有宣稱跨 DB 不可變觸發器已部署。

## 6. 交易、競爭與失敗處理

- 每個服務實例都必須明確提供引擎；每次操作自行取得新連線，不接受外部 Session、Connection 或交易。拒絕記憶體 SQLite、共享單一連線池及未啟用外鍵的連線。另拒絕 SQLAlchemy／driver 自動提交及非 legacy 交易模式；讀寫均明確開始實體交易，避免設定使整批回滾失效。
- SQLite 完整讀取明確開始實體交易，避免 driver 的舊交易模式讓多個查詢讀到不同狀態。初步讀取與新寫交易分開，避免 deferred read 升級寫入死鎖。
- 新批次由資料庫唯一鍵競爭。只把已知批次／請求／預覽／保存身份唯一鍵當可重試碰撞；其他外鍵、CHECK、成本列唯一鍵、觸發器及非 busy 錯誤直接傳出。
- 預設重試期限 2 秒、最多 50 次、間隔最多 0.05 秒；SQLite driver busy 等候為零。每次先回滾並釋放連線才睡眠，不在持鎖期間等待。
- 期限限制的是重試與睡眠，**不是硬即時中斷執行中的 SQL、連線池等候、磁碟 I/O 或注入函式**。999 張測試可另指定較長重試預算；正式量級性能尚待驗收。
- 同內容重試回原整組及建立時間；異內容立即拒絕。不在重試中配號、讀主檔、計價、套用公式，亦不循環呼叫各自提交的舊單品保存。
- [`AtomicSnapshotConflict`](../engine/development_atomic_snapshot.py:21)：保留缺漏、身份／內容／版本衝突或已存資料受損，需停止並調查，不修改保留來強行重試。
- [`AtomicSnapshotTimeout`](../engine/development_atomic_snapshot.py:25)：可以使用原請求稍後查回；不要生成新身份猜测提交是否成功。其他資料庫／睡眠錯誤保留原異常。

MySQL／MSSQL **僅編譯 DDL，runtime 明確拒絕**。未驗證其鎖、隔離層級、錯誤碼、字元集／定序、索引容量、交易引擎、故障切換或正式併發。不要移除方言檢查後直接上線。

## 7. 未來正式表映射與核准

本批未使用 [`QuoteSnapshotDocument`](../database/models.py:284) 或 [`ordqdt_ai`](../database/models.py:228)保存開發內容，兩者既有欄位不變。舊非正式關聯草案保留歷史語意，不改版本冒充正式。未來映射至少須審核：

| 開發快照資料 | 正式映射待辦 |
|---|---|
| 批次／子文件／來源／行與數量 | 核准新的正式版本及正式批次到多張獨立單號的關聯；不能直接沿用非正式描述版 |
| 每張保留號、五位成本序號、完整路徑 | 維持各張自己的序號與來源歸屬，核准正式表複合外鍵及唯一鍵 |
| 規格／部位／選項、說明、單位 | 舊表代碼 10、說明 40、路徑 100、單位 5 字元；開發版較寬，**不得截短**，須先核准容量或明確拒絕正式映射 |
| 原數量／成品數／每件數、用量與價格證據 | 新增正式完整文件欄位或關聯；舊成本表並未容納所有證據 |
| 精確十進位成本、單價與金額 | 舊表為浮點欄位；正式精度、decimal 儲存策略與歷史相容須 DBA／業務核准，不把字串直接轉 float 當無損 |
| 來源程式、來源歷史、條件／圖面證據 | 不等於登入人員；正式人員代碼、身份、授權、核准角色及有效期另建受控契約 |

正式順序仍為：全部正式前置關卡通過 → 固定完整未配號內容 → 第一次正式確認前保留整組 → 建立含號正式預覽 → 同版兩次正式確認 → 正式全部文件／成本列同交易保存。必須另有正式權限與身份、完整來源語意、工程／產品線／含價核准及受控部署，不能用本批保存成功替代。

T29 原始交付只有完整開發服務讀取；後續 T30 已另提供獨立開發唯讀 UI 與非客戶用途輸出，見[開發唯讀查閱操作說明](開發唯讀查閱操作說明.md)。仍無正式受控授權、逐張客戶輸出或正式搜尋介面，不把成本及來源送模型或寫私人日誌。
