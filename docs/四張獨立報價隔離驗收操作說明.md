### 目前只有兩個操作

1. **貼上完整來源，按「產生四張成本明細」。** 第一次產生時自動準備本模式已驗證的空主檔／流程庫；已有資料不覆寫。四張全部計算成功才顯示完整成本表與測試號碼。
2. **看完四張，按「確認並完成報價（測試存檔）」。** 一次記錄「確認並測試保存」，同一交易保存原固定四張；畫面顯示「已完成測試報價，共4張」。不是正式開立或真實價格核准。

四張完整中文單頭、12 欄成本、單張金額及批次固定總額保留；不合併或略過零價工序、不把缺成本當 0、不用展示列重新加總金額。四個分頁切換不查價。

主畫面只保留「測試模式／合成成本，僅測試存檔」提醒。折扣預設 0、操作標記固定「本機測試」，合成設定由測試預設提供，沒有假裝使用者已逐項接受。折扣、樣本、設定、正式缺口、背景紀錄、歷史及完整文字／JSON 下載均在預設收合的「進階」區。

### 修改、失敗與歷史

- 修改來源或折扣後，舊表移到失效歷史區，不能完成；重新按「產生四張成本明細」會自動建立新版本，不需手動管理身份。
- 產生或配號未完成：再按產生鍵。保存未完成：再按同一完成鍵。相同內容雙擊、保存重試及並行不重複配號或存檔，不重新查價。
- 重繪、完成、下載及歷史查閱使用原固定內容；第 2／4 張保存出錯時整批回滾，不留下半批。
- 進階歷史明確顯示「舊兩次核對」或「單次測試確認」。舊資料可讀、可下載、不遷移；舊未完成資料可重新產生成目前測試版本，不在背後補造兩次確認。
- 原文與成本只存專用本機資料庫及使用者下載；下載後需自行保管。未知／損壞資料庫不覆寫修復。

- 解析階段僅顯示來源、尺寸候選、成品數、專屬／適用共用要求與真實缺口，明示尚未計算。沒有成本列時不填零元，不顯示可保存或假通過燈號。

## 2. 私有資料政策

[安全初始化](../acceptance/bootstrap.py:134)只接受**全新目錄**，建立目前使用者擁有、群組及其他人無權限的私有目錄及檔案。重開時核驗標記、manifest、inode、資料庫識別及開發六表；拒絕任意既存庫、正式庫、符號連結、權限不符、替換與覆寫。不接受使用者自行指定資料庫連線字串。

| 管理檔案 | 用途 |
|---|---|
| [識別標記與 manifest](../acceptance/bootstrap.py:25) | 綁定這次管理目錄、檔案身份及版本；不得編輯 |
| [master.sqlite](../acceptance/bootstrap.py:25) | 明確載入的合成主檔，計算時使用唯讀交易；不得手改成本或規格 |
| [workflow.sqlite](../acceptance/workflow.py:136) | 不可變請求、重試身份、前版追溯、固定預覽、兩次確認與失效紀錄 |
| [snapshot.sqlite](../acceptance/bootstrap.py:25) | 獨立開發六表：兩張配號登錄與四張原子快照／關聯／成本表，與正式 Base 分離 |

使用者貼上的完整原文及成本會保存在選定的私有目錄，並出現在明確下載的文件中；一般診斷日誌不記錄原文。瀏覽器下載目錄不受本模式權限管理，下載後須自行依公司政策保管。禁止把私有資料加入版本控制。本次不新增忽略規則，建議使用上述工作區外路徑。

不要刪除、重建或替換資料檔來處理失敗。識別綁定 inode，複製檔案到新庫不會自動成為可操作管理庫；本次**不提供搬移、備份還原或修復工具**。損壞會拒絕繼續，應停止操作並保留現場。單機可信操作人的防護不是抵抗同 UID 惡意程式／管理員的作業系統沙箱，也不宣稱斷電或遠端檔案系統耐久性。

## 3. 實際操作

1. 啟動後按「明確載入合成主檔／初始化或續作」。已完成的一半不覆寫，只補建仍空白的另一半；已有未知或損壞結構會拒絕。
2. 填寫操作人，**明確貼上來源**，或按「載入去識別化樣本」。預設來源為空，不自動讀私人工單。若使用原案例，只貼來源前九行；第十一行後的預期輸出不可混入。
3. 按「解析並展示四張來源（不查價）」，核對順序、完整專屬／共用文字與數量。來源採 LF 純文字；分類標題可以省略，若提供僅接受單一環式會議桌生產工單標題。訂單行接受可選數字括號前綴、8／9 位日期式單號與短客戶識別，不要求公司後綴；客戶識別限 2–24 個連續中英文字，不接受夾帶規格。品項的面條件／走線可以位於數量分隔符後，仍完整保留原文及需求位置。未知行、重複需求或超出本案例的規格會阻擋，不能猜補。
4. 直接閱讀主畫面八項合成設定與中文真實缺口，逐項勾選必要合成假設，再勾選已核對來源。這些勾選表示**採用示範假設**，不是公司或工程核准；不需要先下載 JSON。
5. 設定共同折扣率，範圍 0 至 0.1；例如 0.05 表示 5%。四張分開套用折扣、稅率及捨入，批次只做十進位加總。稅率固定為本版示範 5%，不可從輸入指定成本或覆寫主檔。
6. 按「建立初版：計算四張、持久身份並配號」。四張全部計算成功才持久保存完整請求與身份，再保留同一台灣 14 位時間前綴及 001～004 號碼。
7. 從四張批次總覽進入四個完整成本表分頁，核對每張單頭、專屬／共用要求、孔位／格位例外、全部規格成本列及表尾金額。技術區可保持收合；分開按「第 1 次核對」和「第 2 次核對」，每次均針對同一份固定含號內容。
8. 按「整批原子保存／重試原身份保存（非正式）」。成功後由既有服務完整核驗查回，仍顯示同一組完整成本表；需要留存原文件時再展開「技術明細／下載」，逐張下載原完整文字及 JSON。

## 4. 修改、失敗與重啟

- 修改來源、順序、操作人、折扣或設定接受狀態會**永久撤銷舊核對**；改回舊值亦不能復活。請重新解析並按「明確建立新驗收版本」，產生新身份，追溯前版，舊號不回收。
- 配號或保存失敗時，持久身份已存在。按「明確重試原身份配號／核驗」或原身份保存；不要另開目錄、刪庫或重新計價。
- 第二／第四張或關聯寫入失敗時，四表交易回滾，不留下半批；先前已提交的配號仍保留。**配號與快照不是跨庫同一交易**。
- 回應遺失或重啟後，從「選擇持久批次」選取原批次，再按「載入歷史及原輸入上下文」。可繼續未完成核對、原身份重試，或核驗已保存內容與下載；不重配原號，不改原金額或建立時間。
- 同內容初版重送及同一前版的新版重送會找回既有身份；不同內容必須明確走新版。並行同階段確認只有一次成功，雙點第一次不能視為第二次。
- 確認、重繪、下載與歷史查回**不查主檔、不重新計價**。查回可能補記已提交服務的結果，因此不是完全不寫流程紀錄的取證工具。
- 文件、下載及其能力旗標都是展示資料，不能上傳或翻旗標轉成保存請求或正式報價。未知／損壞身份不會自動補成成功。
