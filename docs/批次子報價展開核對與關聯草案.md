## 1. 本批界線

2026-10-01 依最新契約新增：**一張來源工單 → 一個穩定批次 → 按品項多張獨立子報價描述文件**。

不是一張正式報價內含多產品，也不是按成品件數逐件開單。本區只核對展開、原文與關聯，**不配正式單號、不計價、不保存正式報價、不啟動建表**。沒有兩次確認、部分開立或自動工程核准功能。

舊[多明細內部試算](多明細內部試算操作說明.md)仍為「全部未捨入品項彙總後一次折扣及稅」的歷史內部工具，**不是新批次金額**。舊[單張多明細關聯草案](多明細快照關聯設計與演練.md)保留，不挪用為批次到多張報價的正式契約。

## 2. 操作步驟

1. 在「生產工單核對」核對工單邊界與來源品項；到「多明細配置草稿」選定一張來源工單並明確轉接。
2. 逐品項指定成品數。也可依[數值候選受控套用說明](工單數值候選受控套用操作說明.md)，人工核對後套用。行尾候選不會在展開時自動變成已指定成品數。
3. 在來源需求帳本逐段指定適用明細與依據。共用文字須明確選取所有適用品項；不明範圍維持待確認。條件的全單、群組、單筆與局部例外仍沿用原核對流程。
4. 填寫「操作人（自填紀錄，非核准簽章）」；展開「批次逐張展開核對與下載（非正式、無金額）」。
5. 按「產生批次逐張展開核對（不配號、不計價）」。只打開區塊或重繪畫面，不會首次自動產生結果。
6. 核對每張的穩定識別、原始來源單號、來源品項、原文行號、成品數、專屬／適用共用文字與待確認項目。可展開完整來源座標、需求／條件依據及圖面紀錄。
7. 可分別下載每張非正式描述或整批核對文件。未確認數量／範圍仍可下載供人工處理，但不表示核對完成，更不能作為客戶正式報價。

只有工單轉接草稿可使用。手動新增或單品轉接草稿不推測來源；來源已改版時須重新轉接。本批不提供下載檔重新匯入。

## 3. 識別、版本及數量

| 概念 | 保存方式與限制 |
|---|---|
| 匯入批次／來源工單 | 保留原識別、來源摘要、分類版本、原始單號、候選與座標，不用報價號覆蓋來源號 |
| 配置草稿 | 原草稿識別及修訂版保留；來源品項識別作為直接轉接配置的穩定識別 |
| 報價批次識別 | 由草稿識別衍生，獨立於來源匯入批次；同一草稿重排不變，同一來源另轉接草稿會形成不同批次 |
| 子報價識別 | 由報價批次及來源品項衍生，不使用路徑、尺寸、成品數或展示位置當識別 |
| 展示順序 | 依目前全部活動配置順序，從 1 起；只描述未來尾碼的位置 |
| 未來三位尾碼／正式單號 | 本批均未配置，不生成時間前綴；順序不等於已保留尾碼或單號 |
| 成本列五位序號 | 未來各張子報價各自從 00001 開始，本區不產生成本列；不能誤作三位報價尾碼 |
| 成品數 | 保存操作者配置的正整數，不拆成逐件子報價，不用每件孔數、配件數或分片數替代 |

批次、子報價描述及關聯草案使用不同的新文件版本，定義見 [`agent/quote_batch.py`](../agent/quote_batch.py) 與 [`database/quote_batch_schema.py`](../database/quote_batch_schema.py)。既有內部試算及舊單張多明細文件不相容，不接受直接轉型或僅更名。

文件保存操作人、草稿及來源摘要、配置、需求、條件、圖面與完整順序。每張下載也保存自身來源、操作人、非正式警語與內容摘要，不只依賴批次總覽。

## 4. 描述、共用範圍與否定

- 專屬描述及適用共用描述保留原文，不自行改字、補字或改成正式規格。
- 每段保存來源行識別、行號、原文與字元起訖區間（起點包含、終點不包含）、需求識別及完整人工依據。
- 已核對需求按其明確目標展開；有效條件的明確作用範圍也保留其引用原文、條件識別與依據。
- 未核對／已失效的共用上下文逐張顯示為待確認，**不宣稱適用**。其他品項的專屬描述不無條件複製到全部子報價。
- 同一行拆成多段時，每張仍展示完整來源行作為上下文；各段的範圍、否定及處置獨立保存，不能因展示整行便把整行加工套到該張。
- 需求帳本漏掉片段時補列完整未覆蓋原文並阻擋核對完成，不隨帳本缺漏一起消失。
- 文字與實際選配／計費分離。本區沒有價格或用量查詢，不自動補孔、選配、重複收費或核准工程。

## 5. 安全阻擋與失效

**結構異常整批拒絕產生文件：**

- 來源批次、分類版本、摘要或工單歸屬不一致；原文、來源行識別／座標或候選被改寫。
- 草稿保存的來源與目前來源逐欄不符，不能只冒用相同摘要通過。
- 來源品項與配置雙向覆蓋缺漏、識別重複、互換來源、跨工單或跨事業別。
- 任一封存品項；新增無來源配置也不靜默略過。須先恢復或修正來源後重新核對。
- 超過 999 品項整批拒絕，不截斷、不循環、不另拆批次。
- 需求文字偽造、座標無效、片段重疊，或範圍／條件引用越界。

**保留全部子報價、但核對未完成：** 未指定／非正整數成品數、需求帳本缺漏、範圍未核對、需工程核定、條件衝突或圖面缺少／失效。非有限數值則拒絕序列化，不輸出假有效數量。

重新展示／下載時，從目前草稿及來源重建並逐欄比對，不查主檔。修改配置、數量、標籤、順序、來源、需求、條件、依據、圖面、折扣、操作人或文件版本，都使舊文件失效；即使篡改後自行重算摘要仍不能通過。封存再恢復也不恢復舊核對結果。

任何產生失敗均清除該草稿的舊結果。切換草稿不展示其他草稿結果。摘要只是內容一致性檢查，不是身分認證、數位簽章或工程核准。

本批用隔離 SQLite 驗證新關聯、同批／同事業別外鍵、唯一鍵、版本及容量限制；合成交易在第二張、第四張或關聯階段失敗時，批次、來源、子報價、橋接、既有文件與成本列六表全部回滾。MySQL／MSSQL **僅編譯待審查 DDL，沒有連線執行**。

### 仍須 DBA／正式服務核准

1. 現場資料庫版本、字元集、定序、索引長度、交易引擎、欄位差異及備份還原／回退。
2. 正式批次與子報價文件版本、保存後不可變及修訂制度；本次非正式版本不可直接充當正式快照版本。
3. 外鍵不能證明每個來源都有子報價、每張都有完整成本列，也不能驗證文件內原文與關聯欄位完全相等；未來保存服務須核對完整文件並在同一交易原子保存。
4. 既有文件表沒有新舊內容類型的關聯約束；橋接外鍵存在不代表可把任意歷史快照接成新批次，必須由正式版本分流服務驗證。
5. 配號同秒衝突、唯一性範圍、有界重試、兩次確認、冪等保存及歷史查閱均未實作。三位尾碼與正式單號的資料表／鎖定設計仍待 T47 定稿。
6. 舊文件維持原內容讀取，不重算、不回填新關聯、不修改已開立單號。
