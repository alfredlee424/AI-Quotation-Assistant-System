# 本機 MySQL 四張主檔報價操作說明

> **2026-10-14：本機啟動命令已導向新版任意品項、逐張固定與保存 UI。** 請改讀[新版工單逐張報價操作說明](新版工單逐張報價操作說明.md)。本文件保留舊四張畫面、歷史格式與當時驗證紀錄；下列四張同交易、不可人工補價等規則僅適用[舊 UI](../local_quote/ui.py)。新版提供舊四張唯讀歷史區，不轉換或覆寫舊資料。

## 1. 功能與啟動

於專案根目錄執行：[./venv/bin/python four_quote_acceptance.py --local-db](../four_quote_acceptance.py:15)。先停止佔用同一連接埠的舊伺服器；服務只綁本機 127.0.0.1，預設連接埠 8501。

- 本機模式不需要目錄參數，禁止初始化旗標；與隔離模式互斥，在匯入隔離模組之前以全新程序分流。
- [本機啟動邊界](../local_quote/bootstrap.py) 使用專案虛擬環境、清理繼承環境；不讀使用者或專案的 Streamlit 設定，Mapbox 金鑰固定空值。
- [設定讀取](../local_quote/backend.py:52) 只取 [`.env`](../.env) 的資料庫連線及工作組，不插值、不取模型設定、不改檔案。僅接受本機 MySQL/PyMySQL 及 UTF-8；拒外部主機、其他後端與連線選項繞道。
- 啟動先唯讀檢查五張主檔與兩張保存表。不得透過一般應用初始化、遷移或種子資料補表；結構不符就停止。
- 原 [隔離驗收啟動](../four_quote_acceptance.py:15) 仍使用目錄參數，原隔離庫與舊歷史不變；真引擎沒有注入隔離模組。

## 2. 簡單操作動線

1. 先選「產品類別（整批適用）」。名稱、代碼來自當前工作組的產品主檔，初始不預選、不猜文字分類。輸入框在選單後方。
2. 貼上原工單：剛好四個「描述-----正整數」品項。可保留日期式來源標頭或「來源：…」；共用要求放四個品項之後。原文完整保留，不截斷。
3. 按「產生四張成本明細」。此時才取得所選類別當次五檔、解析及計價；不建立資料庫預覽、不保留正式號碼。
4. 如有歧義，只顯示必要主檔候選。材料、板厚、木腳寬度、線盒顏色、走線槽型式等不預選第一筆。選候選僅重建配置與缺項，不重算；補齊後再按同一產生按鈕。
5. 檢視四個分頁的 12 欄中文成本表、每張金額及四張合計。每張序號各自從 00001 開始；成品數在批次總覽，表內區分每件項目數與本張總項目數。主檔未提供的單位顯示「未提供」，不猜單位。
6. 全部四張成功固定後才出現「確認並完成報價」。一次點選即保存，不要求八項勾選、操作人欄位或另一次工程核准。

修改類別、原文或已選候選會撤銷舊成本與保存資格；材料上游改變，也會撤回不再適用的下游選擇。初始未選類別及單純瀏覽都不解析／計價。

### 可解析的最小來源形狀（僅示意，未替使用者決定材料）

    平直60X180-----2 面無孔
    平直70X120-----1
    平直70X150-----3
    平彎90X180-----1

仍須由使用者選擇主檔缺少的必要配置，並且每條啟用路徑都必須通過主檔與用量驗證。數字尺寸只是與同類別主檔規格的精確標籤匹配，不做未核准的單位換算或近似尺寸替換。

非 CMT1 類別提供「主檔配置-----1」的受限合法主檔選擇入口，不沿用環式語意或按件政策；不能因此宣稱餐桌／其他會議桌已自動理解。精確部位指示亦可用[解析器支援的主檔語法](../local_quote/business.py:1)，仍受完整路徑及代碼白名單檢查，不能輸入價格／用料繞過主檔。

## 3. 實際成本與固定內容

**成本＝成品數 × 每件項目數 × 用料量 ÷ 裁切量 × 採購單價。**

- 類別、結構、規格、價格及用量均由當次唯讀取得的主檔提供，不使用合成驗收資料或歷史明細作價格答案。
- 用量依該路徑的驅動部位及當張所選規格碼取得，不拿材料碼代替尺寸碼、不把 60×180 的用量套到 70 系列。
- 缺價、缺用量、重複規格、未知需求或非有限數值均阻擋；缺資料不是 0。零價結構容器保留，其名稱來自主檔。
- 僅 CMT1 可使用[既有按件清單](../engine/pricing.py:11)，且只限該路徑完全没有用量表時；有用量表但缺所選尺寸不得回退 1／1。
- 報價係數由本次產品主檔讀取。**本模式折扣固定 0%，未稅小計外加 5% 稅，總報價含稅**；逐張採既有核心的計價及捨入政策，批次只加總四張固定含稅金額。
- 無孔禁止啟用桌面孔位路徑；第一張不會因共用文字被加孔。未理解字句不轉成生產備註或假核准。
- [固定預覽](../local_quote/storage.py:192) 包含版本、批次識別、完整來源、產品類別、成品數、配置、需求對應、成本證據及金額。未保存前只在瀏覽工作階段記憶體；沒有正式號碼。

## 5. 保存位置、交易與重試

- [保存服务](../local_quote/storage.py:336) 只在 UI 確認後寫入既有 [`ordqdt_ai`](../database/models.py) 與 [`quote_snapshot_document`](../database/models.py:284)。沒有新增任何批次、保留或開發表。
- 四張及其全部明細同一交易，失敗全部回滾；不是循環呼叫四次各自提交的單品保存。
- 單號在確認交易中配置：台灣時間 14 位前綴加 _001～_004，依來源順序；預覽只顯示待配號。
- MySQL 使用資料庫範圍的連線持有 advisory lock，取鎖等候最多 5 秒；同秒碰撞等待下一秒，有界重試。檢查兩張既有表並使用現有唯一鍵，不改 schema。最後同一連線釋放鎖；鎖狀態不明則使連線失效，避免放回連線池。
- 同一固定預覽的重試回傳原四張結果；同批次若已有部分或內容不同則拒絕，不自動補半批或覆寫。外部程式若不遵循本協定，碰撞由現有唯一鍵及交易回滾保護，不宣稱能控制其他程式。
- 保存只重新核對表結構／歷史，不重讀規格價格或重算。確認時間及四張實際號碼寫進新版本文件。
- 每張文件保存前檢查 UTF-8 **65535 bytes** 容量（含確認時間、批次與原文），同時檢查成本序號及欄位字元長度。不截斷原文、編碼或規格名稱，也不扩表。
- 新文件明確標記為本機四張子快照第 1 版，由[本機歷史讀取](../local_quote/storage.py:432)查回；不偽裝成舊單品或開發快照。明細仍可由[舊明細讀取入口](../database/repository.py:484)按單號讀取，已做隔離相容測試。
- 展開「歷史報價」載入最近已保存批次，可查回四張並下載 JSON；只读固定文件，不查價、不重算。

**保存失敗請先重試同一畫面、同一固定預覽，避免另建批次。** 未保存工作階段不是持久草稿；刷新／程序終止可能失去記憶體狀態。若在未知提交狀態下失去工作階段，先查歷史，不要直接重新產生並保存同需求。下載文件僅供查閱，不能匯入並繞過候選驗證。
