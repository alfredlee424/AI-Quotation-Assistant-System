## 1. 交付與安全界線

2026-10-06 新增獨立入口 [`development_inspection.py`](../development_inspection.py) 及[命令與跨程序測試](../test/test_development_inspection_cli.py)。將既有四種唯讀服務接到可明確操作的命令介面，提供固定版本 JSON 報告及退出碼；**不是正式維運、備份還原、修復或恢復配號工具**。

- 預設拒絕：缺少操作、路徑或 [`--development-only`](../development_inspection.py:51) 聲明，均不呼叫檢查服務。
- 只有參數全部通過後才載入所選服務；匯入入口、求助及拒絕執行不建立資料庫連線。不匯入應用設定、正式 ORM／連線、模型或 UI，不讀私人環境檔或工單日誌。
- 不掃目錄、不猜環境設定、不自動找庫、建庫、建受檢表、配號、保存、刪除、合併或修補。僅沿用服務在私有記憶體庫編譯參考結構的行為。
- 操作聲明不是登入、來源認證或 DBA 核准；檔案路徑不能證明是開發庫。只限可信開發人員對有權讀取的隔離合成庫／允許的開發副本使用，不可指向正式 ERP。
- 本批不修改四種服務、資料表、應用入口或既有配號／原子保存／查閱行為。T43／T45／T31、正式 E01–E09 及所有正式核准均保留待辦。

## 2. 準備及操作

先由可信人員準備既存、最好已停寫的隔離副本；保留原始庫，不要為了「修復」而刪表重建。命令不建立範例資料。

在專案根目錄使用[指定虛擬環境](../venv/)。求助命令（不讀資料庫）：

[`./venv/bin/python development_inspection.py --help`](../development_inspection.py:45)

以下路徑僅為示例，須替換成經確認的隔離副本，不是專案附帶的資料檔：

| 操作 | 命令示例 |
|---|---|
| 六表結構 | [`./venv/bin/python development_inspection.py schema --development-only --database ./isolated/reference.sqlite`](../development_inspection.py:101) |
| 單庫六表完整性 | [`./venv/bin/python development_inspection.py integrity --development-only --database ./isolated/reference.sqlite`](../development_inspection.py:104) |
| 雙庫配號登錄 | [`./venv/bin/python development_inspection.py registry --development-only --reference ./isolated/reference.sqlite --candidate ./isolated/candidate.sqlite`](../development_inspection.py:107) |
| 雙庫完整快照 | [`./venv/bin/python development_inspection.py snapshots --development-only --reference ./isolated/reference.sqlite --candidate ./isolated/candidate.sqlite`](../development_inspection.py:110) |

1. 不接受連線 URL、檔案 URI、缺檔、目錄或末端符號連結；雙庫不接受同檔與硬連結自我比對。路徑含空白時須依 shell 規則加引號；問號、井字號及百分比等普通檔名字元由既有服務編碼為唯讀 URI，不當作連線選項。
2. 不接受縮寫、重複旗標、參數檔、自訂輸出路徑、修復旗標或混用單庫／雙庫參數。參數錯誤只回固定提示，不回顯未知值、路徑或原始解析例外。
3. 結構預設兩秒，其他操作預設十秒；可指定 [`--timeout`](../development_inspection.py:58)，限大於零且至多三十秒的有限數值。沿用各服務期限、容量及 SQLite 允許清單，不重試整次檢查、不擴增容量。期限不是 Python 匯入、單次 JSON 處理或作業系統 I/O 的硬即時保證。
4. 每次只呼叫一個所選服務；完整快照對帳自行在各端同交易驗證內容，不能以先前結構或完整性報告當通行證。
5. 父目錄權限、檔案替換競爭、來源真實性與停寫由可信操作者管理；不宣稱可抵抗惡意管理員或任意不可信資料庫。拒絕私人環境檔及工作區日誌路徑只是避免誤操作，不是完整檔案系統沙箱。

## 3. 四種報告不可互相取代

| 操作 | 證明範圍 | 仍可能通過的反例 |
|---|---|---|
| 結構 | 六表宣告、鍵、約束、索引、觸發器符合目前契約 | 缺成本列、未知持久文件、空庫、舊備份 |
| 配號登錄 | 兩表原始全欄位及全域唯一值歸屬對帳 | 快照缺列；兩端登錄共同損壞／過期；不核驗完整文件 |
| 六表完整性 | 單庫結構、容量、保留請求及所有已保存文件內部一致 | 合法一致改寫、整組刪除、健康舊備份；四表全刪只能列保留未保存 |
| 六表完整快照 | 兩端各自通過完整性後比較全部六表內容 | 共同過期、共同整組刪除、共同合法重寫；不是權威來源認證 |

双庫兩端是依序獨立讀取，不是跨庫同時快照或同一復原點證明。未保存的完整保留另列計數，不推定從未保存，也不可回收。

詳細資源上限與同交易契約沿用：[結構檢查](開發唯讀結構前置檢查.md)、[配號登錄對帳](開發配號登錄唯讀對帳.md)、[六表完整性](開發六表唯讀完整性檢查.md)、[六表完整快照對帳](開發六表完整快照唯讀對帳.md)。入口不將四個結果合併為「可部署」結論。

## 4. 退出碼及輸出

| 退出碼 | 意義 | 輸出 |
|---|---|---|
| 0 | 所選檢查完成且未發現該範圍差異；或單純求助成功 | 檢查為一份完整 JSON；求助則為文字、沒有報告 |
| 1 | 結構／對帳完整完成，但發現差異 | 一份完整差異 JSON，須停止並調查 |
| 2 | 參數、路徑或開發用途聲明無效 | 標準輸出空白；標準錯誤固定提示 |
| 3 | 結構／內容核验、容量、期限、鎖、讀取、依賴載入、序列化或輸出失敗 | 檢查／序列化失敗不提供部分報告；標準錯誤固定提示 |
| 130 | 程序收到可捕捉的人工中止 | 固定中止提示；不可視為已完成 |

內容檢查損壞不是「成功完成的差異」：例如完整快照任一端缺成本列為退出碼 3，而兩端各自完整但整組資料不同為退出碼 1。結構檢查遇到缺表可以完整列出差異，為退出碼 1；其他完整性服務遇到缺表會拒絕整次。

[輸出封套](../development_inspection.py:155)包含獨立版本、操作、狀態、退出碼、警語及服務報告。明確投影已知欄位，不自動序列化服務未來新增的欄位；包含各層報告版本及警語，全部報價、確認、保存、恢復配號能力固定關閉。

報告只含已知表／欄位、差異類別、計數及摘要，不含來源路徑、身份、保留號、客戶原文、成本金額、任意 SQL 或堆疊。JSON 採 ASCII 跳脫，解析後可還原中文；不寫事件日誌、不快取舊報告、不持續監控，重跑才重新讀取。

**退出碼 0 不是正式核准，也不能僅憑它判定收到有效報告**，因求助亦為 0。自動化使用者須檢查完整 JSON、輸出版本、操作及狀態，保留警語；摘要不是簽章，輸出也不是授權憑證。

報告會先完整建立及序列化，再一次寫入標準輸出並刷新。**管線、終端或磁碟在寫出時失敗仍可能留下截斷資料**；輸出不是原子檔案保存協定，必須以非零退出／缺少完整 JSON 視為失敗。命令不提供輸出檔選項；shell 重導向的覆寫、存取權限與保留期限由操作者負責，避免把目標設為來源資料庫或其他既有重要檔案。
