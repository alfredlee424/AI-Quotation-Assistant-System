# T31 開發跨程序故障復原驗收

> **2026-10-05 後續：** 已另新增 [T43 開發備份／還原驗收](開發備份還原驗收.md)，使用隔離 SQLite 線上備份、還原新庫與跨程序查閱重試；包含 WAL 主檔複製及舊 registry 風險反例。以下為 T31 原批紀錄；正式備份維運、權威對帳、部署與跨 DB 驗收仍待。

## 1. 範圍與限制

本批接續 T47 開發配號保留、T29 開發原子保存及 T30 唯讀查閱，補上真實跨程序整合驗證。**保存及輸出的仍是開發資料，不是正式報價，也不是兩次正式確認的端到端驗收。**

本批只新增[整合測試](../test/test_development_process_integration.py)與[測試子程序](../test/development_process_worker.py)，沒有變更應用、計價、正式保存、配號或唯讀服務，也没有增加應用入口、文件匯入器或部署功能。測試沿用[合成四品項請求](../test/development_atomic_fixtures.py:19)，不是將非正式試算／兩次核對文件轉成可保存內容。

T31 僅補強開發驗證；T28／T29／T30／T47 的正式整合、業務／工程／產品線／含價／身份權限／DBA 核准與正式端到端驗收仍待，不勾選完成。

## 2. 隔離與同步方式

- 父程序使用[既有隔離測試設定](../test/conftest.py)，只在測試暫存目錄明確建立六張開發表。無正式表遷移，無私人來源資料。
- [子程序](../test/development_process_worker.py)使用與父程序相同的虛擬環境解譯器，以隔離模式啟動；不依賴環境提供的模組搜尋路徑。只接受工作區外已存在的暫存資料庫。
- 子程序在第三方／專案匯入前安裝稽核防護，禁止私人環境檔、工作區日誌、網路及正式連線／計價／保存模組；不能假設父程序的測試替身會跨程序繼承。
- 父子程序以標準輸入／輸出確認寫入同步點，沒有用任意延遲猜測交易進度。同步、等待與輸出收集均有超時；結束時回收子程序及管線。
- 硬中止只作用於本測試建立的子程序，沒有透過應用例外處理或連線清理模擬回滾。這驗證程序中止復原，**不等於主機斷電、磁碟毀損或備份還原驗收**。
- 唯讀子程序以檔案唯讀模式與 SQLite 操作允許清單讀取；禁止寫入、建表及附加資料庫。所有資料與輸出均為合成測試內容。

## 3. 驗收矩陣

| 案例 | 驗證內容 |
|---|---|
| 配號尚未提交時硬中止 | 第二／第四個保留子項已寫入、或提交前中止；六表恢復原狀，後續可完整重試 |
| 保存尚未提交時硬中止 | 第二／第四張子文件、來源關聯、成本首列或整批提交前中止；四表全回滾，已提交保留完全不變 |
| 保留提交後回應遺失 | 保存仍不存在；新程序以原請求恢復保存，不回收保留或改號 |
| 保存提交後回應遺失 | 重啟回傳原完整文件、建立時間、四張號碼及逐張輸出；禁止重試讀時鐘仍成功 |
| 跨程序同內容競爭 | 兩程序均通過初次不存在檢查後，第一個先提交；第二個確實觸發資料庫唯一鍵衝突並重試回原組，非僅順序呼叫兩次 |
| 未提交批次可見性 | DELETE 與 WAL 日誌模式下，寫者停在第二張子文件；另一唯讀程序看不到半批，提交後才可讀完整組，中止則仍無快照 |
| WAL 同交易讀取 | 讀者已讀批次表但尚未核驗其他表時，另一程序提交 registry 或成本列破壞；當次維持原一致版本，下一次明確查閱拒絕受損內容 |
| 異內容／持久資料損壞 | 重啟後異內容保留／保存拒絕；缺保留子項或成本列，保存及查閱均拒絕且不修補 |
| 完整輸出 | 四張／11 件、固定順序、相同路徑各張獨立五位序號、完整共用／專屬與來源、精確數值及原捨入差額、非正式警語均保留 |

同交易讀取成功只表示「該次交易看到的版本完整」，不保證交易結束後資料仍未被管理員改動。展示／切張／下載不重查資料庫；再次明確查閱才會重新核驗。沿用[T30 新鮮度契約](開發唯讀查閱操作說明.md)。

四張各未稅 0.34、批次未稅 1.36、批次含稅 1.40；每張原稅捨入差額 -0.01 保留，不重算或湊數。測試是固定內容持久性驗證，不認證合成金額符合正式產品計價政策。

## 5. 開發復原原則

1. 回應遺失不代表交易失敗。保留完整原請求與身份，以原內容重試，不生成新身份猜測結果。
2. 保留存在、快照不存在時，可在開發隔離環境以原請求再保存；不能回收孤兒保留或換一組號碼。
3. 保存成功後，以完整身份及版本唯讀查回整批，不走單張捷徑或重新查价。
4. 發生內容衝突、缺列或摘要不符時停止；不可自動補寫、刪除再建或沿用先前畫面作為目前有效結果。
5. 正式備份／还原、跨資料庫交易、故障切換、正式兩次確認及授權，仍須另案核准與驗收。本測試不是正式維運操作腳本。
