# 生產工單核對：階段 1 第一批交付

## 1. 已完成範圍

2026-09-23 新增獨立「生產工單核對」工作區，與原有單品報價及 13 欄歷史報價匯入分開。

目前可將來源切分成多張工單與多筆明細候選，保留原文、行號、分類、數量原文及人工修正紀錄。這是需求核對草稿，**不是正式多品項報價**。

以階段 0 的八張去識別化樣本合併輸入，可切出八張工單與 21 筆來源明細候選。21 筆包含桌面、腳座與改裝項目，不代表 21 張成品桌。

2026-09-24 已加入[尺寸、數量與簡寫唯讀診斷](工單尺寸數量診斷操作說明.md)，可查看明確公分／毫米換算及歧義提示；不自動確認單位或套用配置。

## 2. 操作方式

1. 在頁面上方「工作區」選擇「生產工單核對」。
2. 貼上原始工單，按「建立／取代核對草稿」。
3. 檢查「完整來源與行分類」，特別是未歸屬工單的內容。
4. 在「選擇工單候選」切換工單，核對每筆明細的原文及數量候選。
5. 標題與未分類行也可能包含材質、位置或加工要求；目前不會自動把它們套用到所有明細。
6. 如切分有誤，在「待修正來源行」選取該行，填寫分類、必要的產品類別線索、修正人及理由，再按「套用分類修正」。
7. 可下載核對草稿保存原文、分類與修正紀錄；下載結果不是報價單，目前不能重新匯入還原工作階段。

### 分類修正例子

| 目的 | 操作 | 注意事項 |
|---|---|---|
| 未辨識到工單起點 | 將正確的來源標題改成「工單起始標題」 | 標準來源單號仍可能未知，會保留警告 |
| 一張工單誤合在前單 | 將分界行改成「工單起始標題」 | 該行成為新單標題，下方來源行歸新單 |
| 多出一張錯誤工單 | 將多餘起始標題改成「補充條件（未核准）」 | 合入前單，但不跨越產品分類標題 |
| 明細沒有破折號數量 | 將該行改成「明細候選」 | 仍顯示數量待確認，不預設為一 |
| 明細其實是加工說明 | 改為「補充條件（未核准）」 | 原文不刪除，也不代表工費已包含 |
| 產品分類有誤 | 在分類標題或工單標題設定類別線索 | 只是文字線索，未對應 ERP 正式產品代碼 |

分類標題會中斷前一張工單；變更它可能影響後續多張單的歸屬或類別線索。請重新檢查所有受影響工單。若將分類標題改成其他行類型，需同時清空其類別線索。

## 3. 原文、識別與版本行為

- 原始文字與原始行內容不因分類修正而改寫；來源內容摘要也不改變。
- 同一批次中，每個來源行、工單與明細都有稳定識別，不以產品尺寸或部位路徑當唯一鍵。
- 修改分類後，未受影響的工單與明細識別不變。拆單／合單後，仍以同一來源行形成的明細也保留識別。
- 明細改成補充行後再改回明細，其識別不變；新工單邊界會有自己的工單識別。
- 每次有效修正增加批次版本並保存修改前後分類、類別線索、修正人、理由與 UTC 時間。
- 過期版本、其他批次的來源行、空白理由、非法分類或將空白行改成明細都會被拒絕，原草稿保持不變。
- 修正人是自填的操作紀錄，不是登入認證或工程核准簽章。
- 重按相同原文的建立按鈕會保留現有修正；不同原文建立新批次並取代核對草稿，不沿用舊修正。
- 輸入已修改但尚未建立新批次時，畫面暫停舊草稿的核對與修正，避免原文與顯示結果不一致。

## 4. 保守解析政策

- 自動識別目前三類產品的常見生產單標題、日期式工單號，以及連續破折號後的數量候選。
- 無法識別的內容保留為未分類，不能依產品必選齊全就視為已涵蓋需求。
- 工單前言與分類標題後尚未歸屬的內容獨立保留，不自動繼承到所有工單。
- 重複來源單號不合併；異常日期不修正，均顯示警告。
- 只顯示最多九位的正整數件數候選。零、小數、分數、科學記號與超長數字不視為有效件數。
- 不換算台尺、不猜基材、板厚、色號或配件用量、不判定庫存面就是轉盤。
- 原始文字符合行尾數量格式，也可能是腳座或工序，因此只稱為「明細候選」。
- 限制每批 100,000 字元、2,000 行；過大輸入須分批。長串破折號缺數量時保留未分類，避免高成本正規式回溯。

## 5. 與正式報價的隔離

- 工單核對不呼叫 LLM、查詢 ERP、計價或建立報價。
- 不覆蓋目前單品報價、對話或確認狀態；切回「單品報價」可繼續原流程。
- 在主程式中，工單核對工作區會先結束頁面流程，不執行單品工作區的初始化／灌入資料，也不顯示單品的正式確認按鈕。
- 現有單品報價工作區仍依原設計初始化資料。進入應用預設的單品工作區後再切換，不會撤銷先前的正常初始化。
- 所有工單與明細都保持待核對狀態；沒有「全部核准」或手動解除正式報價阻擋的按鈕。
- 本批次不提供正式規格選配、金額彙總、数据库保存、下載檔還原、圖面解析或原文行編輯／排序。

核對草稿目前只存在工作階段。下載文件含原始業務文字，請依公司權限及保管政策保存；不要當成可公開的去識別化測試資料。
