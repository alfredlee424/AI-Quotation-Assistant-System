# 圖面依賴與版本核對：階段 5 第三批交付

## 1. 功能與交付界線

2026-09-30 在「多明細配置草稿」加入「圖面依賴與版本核對（非工程核准）」。

可登記影響尺寸、定位或規格的圖面依賴，保存圖號／文件識別、版本、人工確認人、確認內容與歷史。缺圖或依據失效時，相關明細不能內部試算，整單不提供合計；不相關且有效的明細仍可單獨顯示內部結果。

**人工核對紀錄不是工程核准，也不是正式報價許可。** 本批不讀取附件、不自動判讀圖面、不套用尺寸、不產生用量或價格、不新增正式資料表。T27 的受控引用、核准權限及正式預覽整合仍待完成。

## 2. 登記缺圖依賴

1. 進入「多明細配置草稿」，選擇要核對的草稿並填寫操作人。
2. 展開「圖面依賴與版本核對（非工程核准）」。
3. 選取圖面適用的活動明細；不得選其他草稿或封存明細。
4. 選取圖面來源需求。工單轉接必須引用至少一筆活動需求；空白／單品轉接允許沒有來源需求，但不因此宣告來源完整。
5. 填寫「圖面用途／待確認內容」及「圖面依賴登記理由」，例如桌面孔位基準、鐵架實內尺寸或轉盤定位。
6. 按「登記圖面依賴（缺圖待補）」。

新紀錄一律為缺圖待補；登記時不接受已核准狀態或價格。每筆依賴有穩定識別，可綁定多筆活動明細，但不自動套用到日後新增的明細。引用需求已有作用範圍時，圖面適用明細不得超出該範圍。

目前採人工登記，不自動辨識所有「照圖」「靠單」或隱含圖面需求。沒有登記圖面依賴不代表没有缺圖，也不能取代原文需求覆蓋檢查。

## 3. 保存人工核對

1. 選擇「待核對圖面依賴」。
2. 在公司既有流程中取得並人工核對正確圖面。
3. 填寫圖面依據識別、獨立的版本欄位、人工確認內容及本次核對理由。
4. 勾選「已人工核對指定版本；了解此紀錄不是工程核准」。
5. 按「保存圖面人工核對（非正式核准）」。

確認內容應具體描述核對的部位、尺寸用途、基準及尚未確定的事項。系統不會因為填入摘要就自動修正尺寸、假厚、分片數、孔位、選配或用料規則。

圖面識別只當文字保存，不會自動開啟網址、讀取本機路徑或下载檔案。操作人由共用欄位取得，不是身分認證或電子簽章；時間使用 UTC。缺圖、無法確定版本或尚未實際核對時，不應保存為已記錄。

## 4. 狀態、歷史與變更影響

| 狀態 | 含義 | 內部試算 |
|---|---|---|
| 缺圖待補 | 已登記依賴，但尚無有效人工核對，或已撤回本次核對 | 阻擋相關明細 |
| 已記錄 | 有對應目前配置與來源的人工確認紀錄 | 僅圖面帳本這一項無待辦，其他來源／幾何／工程關卡仍生效 |
| 需重新核對 | 配置、來源、條件、引用需求或版本已改變 | 阻擋相關明細，不沿用舊結果 |

- 修改適用明細的產品、數量、規格或每件項目數量，相關圖面核對失效。
- 修改來源內容、引用需求的處置／範圍／依據，或相關明細的條件，相關紀錄失效。
- 封存目標明細會使紀錄失效；恢復明細或改回原尺寸不會自動恢復舊核對。
- 修改無關明細配置，不使其他明細的圖面紀錄失效；單純排序不影響圖面核對，但整單舊試算仍失效。
- 同一草稿中，同一圖號更新為不同版本後，其他仍引用不同版本的已記錄依賴會失效，須分別重新核對，不會靜默更新所有摘要。
- 撤回核對使用「標記缺圖／撤回本次核對」，須有理由。歷史圖號、版本、確認人及內容仍保留。

本批不提供刪除依賴或任意縮小其作用範圍的操作，避免移除缺圖紀錄後繞過阻擋。請先完成來源需求拆分與適用範圍核對，再登記圖面。若登記後引用需求被拆分，舊依賴保留失效，不會自動改接子需求；目前須重新建立來源草稿並逐項核對，而不是刪掉舊紀錄解鎖。

不主動監測外部文件版本或撤銷狀態；得知圖面變更時，操作者必須登記新版本或標記缺圖。此帳本不是文件管理或簽核服務。

## 5. 內部試算與資料隔離

- 圖面帳本及歷史包含於配置草稿下載，內部試算亦保留圖面報告。
- 新增、核對、撤回或異動圖面內容後，整單舊試算失效；畫面不會重新查價，須明確重新執行。
- 內部試算使用新版驗證契約，舊版試算不混用；任一活動明細未試算或存在封存明細時，不顯示整單合計。
- 即使所有圖面已記錄，未核對來源、非標待工程核定、未驗證孔位幾何、缺主檔或缺用量仍各自阻擋。
- 原始單品草稿、正式單品預覽與歷史報價不受修改。既有正式入口不能接受多明細內部配置作為已完成工單報價。
- 圖號、版本、確認摘要及操作歷史不加入 LLM 配置上下文，也沒有提供模型可呼叫的圖面核對工具。
- 草稿只保存在工作階段及下載資料；下載檔不支援重匯入。圖面引用及內部成本可能含商業資訊，須依公司資料政策保存。
