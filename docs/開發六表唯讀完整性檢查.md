# T43 開發六表唯讀完整性檢查

> **2026-10-06 雙庫續作：** 新增[六表完整快照唯讀對帳](開發六表完整快照唯讀對帳.md)，每端同交易重驗本文完整性後再比較全部內容，可揭露單庫報告計數相同但內容不同、或配號一致但已保存四表整組遺失。共同過期／全刪／一致重寫仍可能相等，不認證權威最新性或恢復配號；本文原契約與正式限制不變。

## 1. 交付範圍

2026-10-06 接續[配號登錄雙庫唯讀對帳](開發配號登錄唯讀對帳.md)，新增[獨立完整性檢查器](../engine/development_integrity_inspection.py)與[隔離測試](../test/test_development_integrity_inspection.py)。填補「結構及兩端登錄一致，仍可能缺成本列」的缺口。

**只核驗既存隔離 SQLite 六張開發表的內部一致性，不是正式部署、資料真實性、最新性或恢復配號授權。** 不接應用、UI、模型或正式保存入口，不讀其他歷史／主檔表，不修補、不建受檢表、不配號、不回收保留。

本批只將既有[快照資料列組裝](../engine/development_atomic_snapshot.py:136)及[保留表頭組裝](../engine/quote_number_reservation.py:196)改成不需實例的靜態方法，以共用既有契約；原保存、查閱、配號、交易及重試語意不變。檢查器不建構這兩個服務，也不呼叫其寫入或查回入口。

## 2. 操作契約

1. 由可信開發／DBA 人員先隔離合成測試庫或允許的開發副本；路徑本身不是授權或開發用途證明。不可據此連正式 ERP。
2. 明確呼叫 [`inspect_development_integrity()`](../engine/development_integrity_inspection.py:188)，提供既存一般檔案的路徑物件。字串、URL、外部引擎／連線／交易、缺檔、目錄及末端符號連結均拒絕。不猜環境設定、不掃目錄或自動選檔。
3. 每次建立自己的檔案唯讀連線，檔名先編碼，結構、容量預檢及全部資料讀取都在**同一實體讀交易**。允許清單只讀六張開發表及結構資訊；拒絕其他資料表、寫入、建表、附加資料庫及提交。
4. 完整成功才回傳 [`IntegrityInspectionReport`](../engine/development_integrity_inspection.py:50)：六表筆數、驗證通過的已保存批次數、只有保留而未保存的批次數，以及結構摘要。不輸出批次識別、實際號碼、路徑、來源、成本或任意 SQL。
5. 任一結構／資料差異、無效型別、容量、鎖等候、期限或讀取錯誤均拋出 [`IntegrityInspectionError`](../engine/development_integrity_inspection.py:45)，不回部分成功、不快取或沿用前次報告。錯誤文字不含原始內容；呼叫端不得自行記錄含敏感區域變數的除錯轉儲。
6. 呼叫端顯示報告時須一併呈現[警語與能力限制](../engine/development_integrity_inspection.py:28)；報告不是授權憑證，所有正式報價、確認、保存及恢復配號能力始終關閉。

父目錄、來源與操作權限仍由可信呼叫端管理。本工具不宣稱可抵抗惡意管理員、檔案替換競爭或未知來源的惡意資料庫。

## 3. 驗證內容

| 層級 | 驗證 |
|---|---|
| 六表結構 | 同一交易重驗完整欄位、型別宣告、主鍵／唯一鍵／外鍵、版本與檢查约束、索引及觸發器；不把外部舊結構報告當通行證 |
| 持久資料型別 | 不把文字、二進位或浮點值強制轉成合法值；全部必填欄位、主鍵及唯一值均核對 |
| 每組保留 | 嚴格重建有版本的保留請求，拒絕未知／缺漏欄位；重新核對完整固定內容、摘要、身份、狀態、數量、台灣時間前綴及全部有序子項 |
| 每個已保存批次 | 解碼完整固定請求，與同庫保留的全部固定上下文比對；依原保存契約重建含號文件、摘要、建立時間及四表投影 |
| 子報價／來源／成本 | 每張、每列完整欄位與固定內容逐一相等；各張五位成本序號、來源、成品數及共用／專屬文字不跨張混用 |
| 孤立／額外列 | 所有子表依批次分組後逐批完整核對；剩餘無主批次、額外子項或成本均拒絕，不能只迭代批次而漏掉孤立資料 |
| 尚未保存的保留 | 保留完整且四表沒有殘留時另列計數；不視為正式開立、不補存、不配新號或回收 |

重建文件只是比對既有固定資料，不查主檔、不重新計价或修改金額。既有精確十進位字串、逐張捨入差額及非正式警語原樣核驗，不重新解讀來源或宣稱工程規則已核准。

T47 單獨保留契約也可存在於六表庫中；它只通過保留契約驗證，不代表可直接保存為 T29 完整快照。

## 4. 資源與一致性界線

- 保留表頭及保存批次各最多 10,000 列；保留子項、子報價、來源關聯與成本各最多 100,000 列。
- 單列全部欄位合計最多 128 MiB 加 4 KiB，六表全部原始欄位合計最多 256 MiB；固定文件與請求另受原契約容量限制。
- **先對六表全部做位元組及筆數預檢，才讀取任何完整內容。** 超量整次拒絕，不截斷、不略過或自動分批。這些上限是檢查器資源界線，不是修改保存服務的單批上限。
- 預設期限 5 秒，允許大於零且至多 30 秒；SQLite 執行進度與各檢查階段都檢查期限。不能硬中斷單次 JSON 解析、文件組裝或作業系統 I/O，也不保證記憶體峰值等於原始位元組上限。
- WAL 並行變更不污染當次讀交易；下次重新呼叫才看到後續損壞。成功報告不代表目前仍未被修改，也不代表已停寫。
- 報告沒有資料內容摘要；同筆數的不同資料可能產生相同摘要計數。不可用報告相等替代雙庫內容對帳。

## 5. 三種檢查不可互相替代

| 工具 | 能證明的範圍 | 仍不能證明 |
|---|---|---|
| [唯讀結構檢查](開發唯讀結構前置檢查.md) | 當次結構符合開發契約 | 資料存在或完整、備份最新 |
| [雙庫配號登錄對帳](開發配號登錄唯讀對帳.md) | 兩端登錄的逐欄差異及唯一值歸屬衝突 | 參考端權威、兩端同一復原點、完整快照有效 |
| 本完整性檢查 | 當次六表中仍存在的保留與完整快照內部一致 | 外部歷史是否遺失、來源真實、最新性、業務／工程核准 |

**健康舊備份、整組資料已完全刪除、六表全空或所有內容被一致重寫，仍可能通過。** 若已保存四表全刪但完整保留仍在，只能列為「保留未保存」，無外部依據不能判斷過去是否曾成功保存。摘要不是簽章，唯讀檢查不是防竄改認證。

正式復原仍須權威登錄／外部紀錄、可信备份來源、停寫隔離、同一復原點、DBA 審查、RPO／RTO、權限／部署及業務工程核准。T43／T31／正式 E01–E09 不勾選完成；沒有新增正式遷移或修復工具。

## 6. 驗收結果

使用 [指定虛擬環境](../venv/) 的 Python 3.14.3 與既有[隔離測試設定](../test/conftest.py)。2026-10-06：

- [新增測試](../test/test_development_integrity_inspection.py)：**131 項通過，7.79 秒**。
- 完整測試目錄：**2039 項通過，208.61 秒**；既有 1908 項全部保留。
- SQLite DELETE／WAL、四張／11 件、跨事業別多批、單獨保留及空六表。
- 六表逐欄篡改、缺列／缺表、孤立額外列、重算摘要、無效 JSON／版本／型別，以及結構、索引、觸發器漂移。
- 結構與登錄均一致但缺成本仍拒絕；健康舊備份通過但雙庫對帳可揭露後續保留。
- 真實唯讀連線拒絕寫入、其他表、附加資料庫及提交；外部未提交交易不被干預。
- WAL 在結構或內容讀取中途提交損壞，當次仍完整一致，下次拒絕；錯誤後關閉連線，不復用成功結果。
- 容量精確邊界、超量前不讀完整內容、特殊檔名、逾時與鎖、全新程序匯入無連線，並禁止私人環境檔、工作區日誌、網路及正式依賴。

僅 macOS／SQLite 隔離開發驗收，未驗收 Windows、MySQL／MSSQL runtime、正式主檔、真模型、惡意檔案或正式復原。沒有讀取私人工單或執行正式資料庫建表。
