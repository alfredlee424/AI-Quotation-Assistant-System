# T43 開發配號登錄雙庫唯讀對帳

> **2026-10-06 六表續作：** 另有[六表完整快照唯讀對帳](開發六表完整快照唯讀對帳.md)，先核驗各端全部持久內容再比較六表，揭露登錄一致但已保存快照不同或整組遺失。本文仍只比較兩張登錄表，不因此改變契約；新工具也不認證權威、最新性或同一復原點，不授權恢復配號。

## 1. 本批交付範圍

2026-10-05 接續[開發唯讀結構前置檢查](開發唯讀結構前置檢查.md)及[備份還原驗收](開發備份還原驗收.md)，新增[雙庫對帳器](../engine/development_registry_comparison.py)與[隔離測試](../test/test_development_registry_comparison.py)。

用途是比較明確指定的兩份隔離開發配號登錄，找出舊備份遺失、額外紀錄、同身份異內容及分岔配號衝突。**不是權威 registry 認證、備份最新性證明、正式復原工具或恢復配號授權。**

不改應用、配號、保存、查閱及模型入口，不提供自動掃描、UI、命令列資料庫搜尋、修補或匯入；不讀其他快照／歷史資料表。T43／T31／正式 E01–E09 及業務、工程、身份、DBA、部署核准仍保留待辦。

## 2. 明確操作契約

1. 呼叫端先備妥兩份**可信、隔離、已停寫的開發副本**，指定比較方向。參考端只是「以此為基準」，工具不認證其權威性、最新性或來源，也不能判定一般檔案是否真為開發用途。
2. 呼叫 [`compare_development_registries()`](../engine/development_registry_comparison.py:163)，提供參考端及候選端兩個既存路徑物件。不接受字串、連線 URL、外部引擎／連線／交易、缺檔、目錄及末端符號連結；同檔及硬連結自我比對拒絕。父目錄與檔案替換競爭仍由可信呼叫端管理。
3. 每端建立自己的檔案唯讀連線，先在同一實體讀交易核對兩張 registry 表的完整結構，再讀該端兩表內容。只在私有無資料記憶體庫建立參考結構，不在兩端建表或修補。配號登錄只有兩表、尚未建立開發快照四表也可對帳。
4. 檢視 [`RegistryComparisonReport`](../engine/development_registry_comparison.py:53)。一致只表示兩次讀取所得 registry 內容一致；有差異立即停止並交開發／DBA 調查，不自動合併、選較新的檔案、補列、回收號碼或重新配號。
5. 後續仍須依完整保存身份逐批執行[既有完整查回](整批原子保存開發操作說明.md)，並另行核准權威配號紀錄、同一復原點、停寫隔離、資料與備份真實性。孤兒保留不代表失效，也不能刪除回收。

完整合成操作範例見[測試](../test/test_development_registry_comparison.py)。工具沒有預設正式連線，不從私人環境檔推測位置。

## 3. 比對及報告語意

| 結果 | 定義 |
|---|---|
| 參考端／候選端列數 | 各表當次完整讀取的筆數，不只比較最大前綴或檔案時間 |
| 遺失列 | 主鍵只存在參考端；候選端遺失整組保留或部分子項都會揭露 |
| 額外列 | 主鍵只存在候選端；反轉比較方向時與遺失列互換 |
| 變動列 | 同一主鍵但任一欄位不同，包含固定內容字串、時間、原文、摘要及逐張映射 |
| 唯一值歸屬衝突 | 兩端相同請求／預覽／前綴／子報價識別／完整保留號，卻屬於不同主鍵；跨事業別也算衝突 |
| 表內容摘要 | 按穩定主鍵摘要排列的全表內容摘要；實際資料插入順序不影響結果 |
| 結構摘要 | 當次使用的兩張開發配號表契約摘要；不是遷移版本紀錄或簽章 |

所有欄位均依[現有 registry schema](../database/quote_number_reservation_schema.py)讀取。固定內容直接參與比對，不信任儲存的摘要欄位，也不解析、正規化或重新序列化內嵌文件；只有空白不同也報差異。型別不符、未知持久版本或非保留狀態均拒絕，不降版或翻狀態。

**這不是完整性驗證器。** 除結構、儲存型別及表頭版本／狀態檢查外，不核驗固定文件內所有業務語意、子項計數、保留時間與號碼的合理性，也不重建整批快照。兩端共同缺少相同列或共同竄改內容，仍可能被判為內容一致；報告從不稱其健康或有效。

## 4. 唯讀、容量與資料保護

- [實際讀取允許清單](../engine/development_registry_comparison.py:88)僅開放主庫結構查詢、兩張 registry 讀取、長度函式及開始／回滾讀交易；禁止其他表資料、寫入、DDL、附加資料庫、提交交易、任意函式及擴充套件載入。
- 完整來源或成本可能內嵌於 registry 的固定內容；本工具**會為比對讀取這些字串**，但不解析、不輸出、不寫日誌。這不同於前一批完全不讀資料內容的結構檢查器；執行者仍須有商業資料的讀取權限。
- 報告只包含已知表／欄位名稱、計數、整表摘要及固定警語，不包含原始識別、單號、來源、成本、路徑、SQL、現場 DDL 或錯誤參數。整表摘要不是防竄改簽章，也不是授權 token。
- 每庫上限 10,000 批次列、100,000 子項列、單列 64 MiB、累計欄位內容 256 MiB。先在同一讀交易取得欄位位元組長度，再取內容；超量整次失敗，不截斷或只抽樣比較。明確計入多位元字元及內嵌零字元。
- 上述限制是本開發對帳器的工作量限制，不更動配號服務每批 999 張及其他既有容量。也不是 SQLite 內部記憶體或作業系統 I/O 的硬上限承諾。
- 預設整次期限兩秒，可明確設定大於零且最多三十秒。兩端共用期限，限制鎖等候、掃描、虛擬機進度與最後彙總；不保證中斷作業系統 I/O。錯誤或逾時拋出 [`RegistryComparisonError`](../engine/development_registry_comparison.py:29)，不回半份報告、不快取舊成功。

## 5. 一致性與不可替代的正式關卡

每一端的結構、表頭及子項在同一實體交易，因此 WAL 並行修改不會混入該端讀取中的半份狀態；下一次明確對帳才看到新內容。

**兩端是依序讀取的獨立快照，不是跨庫原子交易。** 第一端讀完後、第二端尚在讀時，第一端可以已經改變；當次一致不能證明目前仍一致。工具不取得兩端寫鎖，也不宣稱已完成停寫。必須由維運流程管理停寫、不可變副本與同一復原點。

| 情境 | 對帳結果與後續要求 |
|---|---|
| 候選備份少了後來保留的整批 | 列出遺失；不能拿健康舊備份直接恢復配號 |
| 同秒兩個分岔庫保留給不同批次 | 揭露相同前綴及完整號的不同歸屬，不按事業別隔離衝突 |
| 兩端都是同一份過期備份 | 可一致，但不證明沒有其他已使用號碼 |
| 兩端共同缺列或共同竄改 | 可一致；仍須既有服務的完整持久內容驗證與可信外部證據 |
| 配號相同但候選缺成本列 | registry 可一致，完整批次查回仍拒絕；不等於整庫一致 |
| 配號已保留但尚未保存 | 孤兒保留可一致；不授權回收，也不是已正式開立 |
| MySQL／MSSQL／Windows／磁碟故障 | 本批沒有這些 runtime 或正式環境驗收，不可直接推論相容 |

正式仍須權威高水位／異地紀錄對帳、備份真實性與加密權限、停寫隔離、同一復原點、RPO／RTO、受控遷移版本、DBA 審核，以及業務／工程／身份授權。沒有新增權威清單匯入或恢復配號入口。

## 6. 驗收及執行

[測試矩陣](../test/test_development_registry_comparison.py)涵蓋空庫、孤兒保留、已保存、DELETE／WAL、雙向差集、同主鍵逐欄變更、同秒跨事業別分岔、內容摘要不可信、未知版本、共同損壞、缺成本反例、兩端結構漂移、唯讀允許清單、路徑安全、容量及位元組邊界、外部交易隔離、鎖與期限、中途失敗、兩端 WAL 一致性及跨庫時間差。

另以全新程序在匯入前封鎖私人環境檔、工作區日誌、網路及正式／配號／保存服務依賴，驗證匯入不連線，跨程序報告摘要一致。資料皆為合成來源；不讀私人工單。

- 新增測試：[`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 ./venv/bin/python -m pytest test/test_development_registry_comparison.py -q -p no:cacheprovider`](../test/test_development_registry_comparison.py:1)。
- 完整回歸：[`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 ./venv/bin/python -m pytest test -q -p no:cacheprovider`](../test/conftest.py:15)。
