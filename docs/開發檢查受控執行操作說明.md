## 1. 交付範圍

2026-10-07 新增[獨立受控入口](../development_inspection_run.py)及[122 項測試](../test/test_development_inspection_run.py)。接續[原唯讀檢查命令](開發唯讀檢查命令操作說明.md)與[離線驗證器](開發檢查報告離線驗證操作說明.md)，填補手工取得退出碼／管線最後退出碼不一定屬於原檢查的缺口。

**每次固定啟動一個既有檢查子程序，直接收集它的標準輸出與實際退出碼，嚴格驗證後才輸出結果。** 不接受外部報告、呼叫端自填的檢查退出碼、自訂腳本或解譯器，不重試整次檢查、不使用舊成功結果。四種檢查服務、原命令、離線驗證器、應用及配號／保存／查閱服務不變。

這是可信本機上的開發工具，不是正式監測稽核、備份還原或恢復配號工具。T45／T43／T31、正式 E01–E09 及業務／工程／身份／DBA 核准均仍待。

## 2. 使用方式

使用[指定虛擬環境](../venv/)，由可信人員先準備既存、允許讀取的隔離 SQLite 合成庫或開發副本。**不可指向正式 ERP**；用途聲明與檔名不能證明來源是開發資料。

求助不讀資料庫、不啟動子程序：

[`./venv/bin/python development_inspection_run.py --help`](../development_inspection_run.py:51)

下列路徑只是示例，不是專案附帶檔案；請依實際隔離副本替換：

| 操作 | 命令示例 |
|---|---|
| 六表結構 | [`./venv/bin/python development_inspection_run.py schema --development-only --database ./isolated/reference.sqlite`](../development_inspection_run.py:51) |
| 六表完整性 | [`./venv/bin/python development_inspection_run.py integrity --development-only --database ./isolated/reference.sqlite`](../development_inspection_run.py:51) |
| 配號登錄對帳 | [`./venv/bin/python development_inspection_run.py registry --development-only --reference ./isolated/reference.sqlite --candidate ./isolated/candidate.sqlite`](../development_inspection_run.py:51) |
| 六表完整快照對帳 | [`./venv/bin/python development_inspection_run.py snapshots --development-only --reference ./isolated/reference.sqlite --candidate ./isolated/candidate.sqlite`](../development_inspection_run.py:51) |

- 所有原命令路徑規則仍適用：缺檔、目錄、末端符號連結、連線 URL／URI、私人環境檔、工作區日誌及雙庫同檔／硬連結自比對均拒絕。相對路徑以呼叫端當前目錄解讀，送到子程序前改為絕對路徑；含空白或 shell 特殊字元時由操作者正確加引號。
- 不接受重複、縮寫、未知或混用單庫／雙庫旗標。不讀標準輸入，不接受報告檔、自訂程式、輸出檔或修復選項。
- [服務期限選項](../development_inspection_run.py:51)沿用原命令：結構預設 2 秒，其他預設 10 秒；大於零、有限且不超過 30 秒。
- [程序期限選項](../development_inspection_run.py:51)預設 45 秒，大於零、有限且不超過 60 秒；涵蓋子程序啟動後的輸出收集及等待退出。可比服務期限短，此時整次失敗，不降級為部分成功。
- **目前限定 POSIX 管線，實測 macOS；Windows 在啟動子程序前明確拒絕為執行失敗。** 未宣稱 Linux runtime、Windows 或其他資料庫已驗收。

## 3. 程序與資源契約

[固定啟動器](../development_inspection_run.py:136)使用父程序當前解譯器、隔離模式及停用位元組碼寫入。命令由內部參數清單組成，不經 shell；只加入固定專案根目錄，不繼承使用者提供的模組搜尋路徑。子程序環境不傳遞父程序變數或憑證，標準輸入關閉，非必要檔案描述符不繼承。

[子程序稽核防護](../development_inspection_run.py:28)在專案與第三方模組匯入前安裝，阻擋私人環境檔、工作區日誌、網路、正式連線／計價／保存依賴，以及建立額外程序。它不是完整作業系統沙箱，不能抵抗遭竄改的解譯器、已安裝套件、原生命令擴充或惡意管理員。服務本身仍以既有唯讀連線、同交易與容量規則檢查明確來源，不隱式建受檢表或修補。

[有界收集器](../development_inspection_run.py:90)同時監控兩條管線，不先無界收集再檢查大小：

| 項目 | 契約 |
|---|---|
| 標準輸出 | 最多 64 KiB；讀到上限加一即拒絕，不截斷後接受 |
| 標準錯誤 | 最多收集 4 KiB；有任何內容即不接受成功結果，不向外回顯 |
| 原程序退出碼 | 只接受 0 或 1，且須與報告操作、版本、狀態、計數及內容契約一致 |
| EOF 與退出 | 須取得兩條管線 EOF 及真正退出碼；印出有效文件後卡住或關閉管線後不退出仍拒絕 |
| 失敗回收 | 逾時、容量、讀取／監控錯誤或可捕捉中止時，終止仍存活的自有子程序，等待回收並關閉管線；不操作其他程序 |
| 清理等待 | 終止後另有最多 2 秒回收等待；若系統無法回收則回失敗，不輸出成功 |

期限不是整個父程序的硬即時 SLA：程序建立本身、檔案系統呼叫、父程序驗證／序列化／最終輸出可能由作業系統阻塞；父程序遭不可捕捉終止或主機故障也不保證執行清理。正式部署仍需外部監督與期限。容量只限制命令輸出，資料庫檢查本身的資源上限沿用各服務文件。

## 4. 輸出與退出碼

[新輸出封套](../development_inspection_run.py:142)包含獨立版本、本次隨機執行識別、操作、狀態、原檢查退出碼、驗證版本、固定警語、關閉的正式能力旗標，以及完整且已驗證的原檢查文件。保留原文件的逐表差異、計數、摘要和全部警語；不把四種操作合併成可部署結論。

不輸出來源路徑、客戶原文、實際單號、成本、任意 SQL 或子程序錯誤。不寫日誌、不保存報告、不提供跨程序查詢執行識別的資料庫。執行識別每次不同，不是權限憑證、簽章或防重放機制。

| 退出碼 | 意義 |
|---|---|
| 0 | 本次原檢查無差異且完整報告驗證通過；或只是求助成功 |
| 1 | 本次原檢查完整完成但發現差異，且差異報告驗證通過；須停止調查，不當作通過 |
| 2 | 用途聲明、參數或路徑拒絕，未啟動子程序 |
| 3 | 平台不支援、啟動／收集／期限／容量／原檢查失敗、報告無效或輸出失敗 |
| 130 | 父程序收到可捕捉的人工中止；子程序的 130 則是本次檢查失敗，父程序回 3 |

求助仍為 0，所以接收者須核對完整新封套，不只看最後的退出碼。新封套不等於原命令文件，不能直接餵給只接受原契約的離線驗證器；內嵌文件可另行驗證，但那不會認證外層執行識別或來源。

完整序列化後才寫標準輸出，**寫出或刷新失敗仍可能留下截斷結果**。本批沒有原子報告保存；自行重導向時仍需保護目的檔、避免覆寫來源庫，並管理權限、保留期限與可信來源對應。

## 5. 不能據此證明的事項

1. 本入口只在可信本機程序內維持「本次選定參數 → 本次子程序 → 實際退出碼與輸出」對應。來源檔案可能在前置檢查與開啟之間遭替換；父目錄、符號連結祖先及來源權限由可信操作者管理，不提供檔案身份鎖定或停寫證明。
2. 封套不含來源路徑，外部保存後不能單靠執行識別重建或認證來源；尚無簽章、可信執行登錄、原子保存或防重放協定。測試特別保留「若可信程式被替換，自洽偽造報告仍可通過」反例。
3. 舊備份、兩端共同刪除／一致重寫仍可能在各自檢查範圍內通過；原服務限制不因加上程序包裝而消失。雙庫仍是各自依序交易，不是跨庫同時快照。
4. 尚待可信報告保存與来源認證、權威配號歷史、備份最新性、停寫／同一復原點、正式遷移／回退、RPO／RTO、DBA／部署／跨平台／跨 DB，以及業務工程身份核准。不得据此恢復配號或開放正式報價。
