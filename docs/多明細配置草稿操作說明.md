# 多明細配置草稿：階段 1 第二批交付

## 1. 功能定位

2026-09-23 新增「多明細配置草稿」工作區。每份草稿可以保存多筆產品配置，各自有產品類別、數量、完整部位選配與明細版本；同一部位路徑在不同明細中不互相覆蓋。

2026-09-24 已另加入[AI 跨明細配置提案](多明細AI配置提案操作說明.md)：先指定範圍、產生並驗證提案，再人工套用。本文件以下的手動配置流程仍可使用。

同日新增[來源需求帳本與問題核對](來源需求帳本與問題核對操作說明.md)，可人工拆分原文、建立選配對照及記錄結案依據；相關變更會使證據失效，正式報價仍未開放。

**目前只做配置，不做整單計價、正式預覽或資料庫保存。** 即使每筆規格都完整，來源需求覆蓋、工程條件及整單計價尚未完成，仍不允許建立報價。

## 2. 進入方式與來源

頁面上方「工作區」選擇「多明細配置草稿」。可以：

1. **新增空白多明細草稿**：再逐筆新增明細。
2. **複製目前單品為新配置草稿**：複製原有單品或 13 欄匯入後的單品草稿，不修改來源。
3. **轉接此工單為新配置草稿**：先在「生產工單核對」完成候選切分，再選取一張來源工單轉接。

每次轉接會新增獨立草稿。可在「選擇配置草稿」切換；不會覆蓋原有單品報價、其確認狀態或工單核對批次。

### 工單轉接

- 每筆來源明細候選建立一筆獨立配置。
- 只保留產品分類線索，不直接推定 ERP 產品代碼。
- 行尾數量仍保存在來源候選中，**不填入活動配置的產品數量**。
- 標題、補充行與未歸屬內容保留，不能因未對應部位而丟棄。
- 不帶入其他工單的來源行與無關分類修正紀錄。
- 若來源批次、分類版本或來源摘要改變，舊草稿保留可查看／下載，但停止編輯；須重新轉接，不自動沿用舊配置歸屬。

### 單品轉接

- 原有產品數量與每件配件數量分開保留，不把配件數量当成成品數量。
- 來源規格、匯入列、警告、未解問題、候選及來源單號保存供追溯。
- 活動配置不沿用舊預覽、正式单號狀態、金額、歷史成本、材料用量或自動選配標記。
- 舊價格只能在來源快照中查看，不作本次計價依據。
- 來源產品／規格尚未對照目前主檔前，不視為已驗證；不存在的歷史路徑不能靜默丟棄。
- 來源折扣保存於整單層，明細內折扣歸零，避免將來重複套用；本批尚未提供整單折扣編輯與計價。
- 拒絕不同事業別、衝突路徑、無效數量或超出目前上限的折扣。

## 3. 管理明細

所有修改都須填寫「操作人」與「本次操作理由」；這是自填紀錄，不是登入認證或工程簽核。

| 操作 | 行為 |
|---|---|
| 新增明細 | 建立新的穩定識別；不預選產品、不預填數量 |
| 明細上移／下移 | 只改顯示順序，不改明細識別、配置或明細版本；整單修訂版增加 |
| 移除並封存 | 不刪除來源或配置；明細移至封存區，保留識別及移除理由 |
| 恢復封存明細 | 以原識別及配置放回活動清單尾端；明細版本增加 |
| 下載配置草稿 | 保存活動／封存明細、來源、阻擋條件、修訂及操作紀錄；不是報價單 |

明細名稱是來源或人工輸入的標籤，不是規格驗證摘要。實際配置以各部位合法選配為準。

相同来源明細在不同轉接草稿中可保留相同來源識別，所有操作仍必須同时符合草稿識別及版本，不能只靠明細識別跨草稿修改。

## 4. 配置產品與部位

1. 選擇「編輯明細」。
2. 勾選「顯示合法選配（唯讀查詢目前產品主檔）」。未勾選前，明細管理不會查詢主檔。
3. 明確選擇產品類別、輸入產品數量，按「套用產品及數量」。
4. 選擇完整部位路徑、正式規格及每件產品的項目數量，再按「套用此部位規格」。
5. 可明確「移除此部位分支」；若涉及互斥材料方案，先移除舊分支，再選新方案。

產品、路徑、規格及必要結構共用既有配置驗證，不另開放自由價格、成本或用量欄位。

- 更換产品只重建目標明細的選配，不清除其他明細。
- 材料方案衝突、規格不存在或數量無效時，整次操作不保存，不留下部分修改。
- 必選缺項可留在配置草稿等待補齊，不代表可以報價。
- 選配成功後，介面保留目前明細及部位焦點，避免下一次操作誤套到第一筆。
- 若主檔查詢失敗，顯示錯誤並保持草稿不變，不使用第一筆或預設規格代替。
- 這個工作區不灌入產品主檔；若資料庫尚無產品，必須依正式資料準備程序處理。

## 5. 版本、隔離與阻擋

- 整單與明細都有版本。配置修改增加目標明細版本；其他明細內容不變。
- 每次操作返回深複製的新草稿，舊物件不被原地更新；匯出內容也與活動草稿隔離。
- 過期整單版本、錯誤草稿識別、其他草稿的明細、非法狀態、未知欄位或未簽名操作均拒絕。
- 排序必須提供完整且不重複的活動明細集合；不能藉排序省略明細。
- 全部明細移除後仍保留封存內容、來源與阻擋條件，不變成可報價的空單。
- 操作提案不得清空來源問題、修改歷史紀錄或直接提供價格。
- 每筆內部配置也保留多明細流程的未完成問題；即使誤送入舊單品預覽入口，仍會被阻擋。
- 來源變更目前採保守的批次版本檢查；同批其他工單改分類也會使舊轉接草稿停止編輯。
